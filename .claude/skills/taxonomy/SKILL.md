# /taxonomy — 카테고리·타깃 목록 관리

작업 폴더: 이 프로젝트 폴더(저장소를 내려받은 폴더). 기준 목록은 같은 폴더의 `taxonomy.md`에 둔다.

## 절차
1. **현황 파악**: `processed/*.json`의 `tags.category`, `tags.target_audience` 값과 각 편수를 표로 모은다. 표기가 비슷한 것(띄어쓰기, 중점, 동의어)을 묶어서 보여준다.
2. **목록 확정**: `taxonomy.md`가 비어 있거나 사용자가 새 목록을 원하면, 현재 값을 바탕으로 목록 **제안**을 만든다. 카테고리는 8개 이내를 권장한다. **사용자가 확정하기 전에는 `taxonomy.md`에 쓰지 않는다.** 확정된 목록은 `CLAUDE.md`의 필수 태그 표 아래에도 한 줄로 요약한다.
3. **일괄 변경 계획**: "id: 이전 값 → 새 값" 표로 보여주고 확인받는다. 매핑이 애매한 문서는 추측하지 말고 개별로 묻는다.
4. **적용**: 확인 후 해당 `processed/<id>.json`의 태그만 수정한다 (다른 필드는 건드리지 않는다). 댓글 문서(`format: 댓글`)는 `parent_id`의 부모 카테고리를 따르도록 함께 바꾼다.
5. **다시 올리기**: 바뀐 문서만 `node scripts/upload.mjs --id <id>`로 dry-run 후 확인받아 `--commit`으로 덮어쓴다 (`--commit`은 `node --env-file=.env scripts/upload.mjs ...`로 실행).
6. **기록**: `reports/ingest-log.md`에 이전→이후 매핑과 재업로드한 id를 추가한다.

## /ingest와의 관계
`taxonomy.md`가 확정돼 있으면 `/ingest`는 그 목록 안에서 카테고리를 고른다. 목록에 맞는 값이 없으면 새 항목을 제안하고 사용자에게 묻는다.

## 금지
- 사용자 확인 없이 목록을 확정하거나 태그를 대량으로 바꾸지 않는다.
