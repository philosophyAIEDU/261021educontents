# /topic-ideas — 다음 콘텐츠 주제 후보 5개

작업 폴더: 이 프로젝트 폴더(저장소를 내려받은 폴더). **입력은 필요 없다.** 사용자에게 질문하지 않고 끝까지 진행한다 (자동 실행에서도 그대로 쓰인다).

## 절차
1. `CLAUDE.md`의 "초고 작성" 규칙 4~6, `structure.md`(2·5·8절), `voice.md`를 읽는다. 없으면 멈추고 알린다.
2. **근거 데이터**를 모은다.
   - `processed/*.json`의 태그·`key_message`·`views`로 **성과가 좋았던 주제**(등급 '상')와 아쉬웠던 주제를 파악한다.
   - **댓글**: `format: 댓글` 문서가 있으면 `reaction_type`이 `질문`·`요청`인 것을 주제별로 묶어 **몇 건인지만** 센다. 댓글 원문은 인용하지 않는다 (규칙 4). 댓글 문서가 없으면 "댓글 데이터 없음"이라고 명시한다.
   - `drafts/`(`weekly/` 포함)와 `reports/topic-ideas.md`의 최근 주제를 확인해 **이미 다룬 주제나 최근에 제안한 주제는 피한다.**
3. **후보 5개**를 만든다. 구성 원칙:
   - 2개 이상은 성과가 좋았던 콘텐츠의 **후속·시리즈**
   - 1개는 `structure.md` 2절의 경향(잘 된 콘텐츠의 공통점)을 살린 **새 주제**
   - 댓글 질문·요청이 있으면 그 주제를 우선 반영한다
   - `brand.md`의 `운영 채널` 안에서 채널이 겹치지 않게 분산한다 (주제·타깃도 brand.md와 맞는지 본다)
   - 주제는 **한 줄**로, 그대로 `/draft <채널> <주제>`에 넣을 수 있게 쓴다
4. 출력 형식(한글 표):

| # | 주제(한 줄) | 근거 | 추천 채널 | 훅 유형 |
|---|---|---|---|---|
| 1 | ... | script-03(조회수 상)의 후속 | 유튜브 | B |

   - **근거는 데이터 출처를 적는다** (어떤 콘텐츠의 성과, 댓글 질문 N건, structure.md 몇 절). 근거가 약하면 "근거 약함"이라고 쓴다.
   - 외부 트렌드·검색량은 조회할 수 없으므로 아는 척하지 않는다.
5. 표 위에 **데이터 한계**를 한 줄로 적는다 (예: "댓글 데이터 없음, 스레드 데이터 없음, 표본 6편").
6. `reports/topic-ideas.md` **맨 위**에 오늘 날짜 제목(`## YYYY-MM-DD`)으로 같은 내용을 추가한다. 파일이 없으면 `# 주제 후보 기록 (최신이 맨 위)` 제목으로 만든다.
7. 채팅에는 표와 한계만 보여 준다.

## 금지
- 성과를 약속하는 표현(예: "조회수 잘 나올 주제")을 쓰지 않는다. "성과가 좋았던 콘텐츠의 후속"처럼 사실만 쓴다.
- `voice.md`, `structure.md`를 수정하지 않는다.
