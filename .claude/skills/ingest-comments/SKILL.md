# /ingest-comments — 댓글 정제·분류·업로드

작업 폴더: 이 프로젝트 폴더(저장소를 내려받은 폴더). **규칙 2가 최우선이다: 작성자 이름·닉네임·프로필 정보는 어떤 형태로도 저장하지 않는다.**

## 0. 입력
- `raw/comments/`의 파일(txt/csv/json 등)을 읽는다. 폴더가 없으면 만든다. `raw/`는 git에 올라가지 않는다.
- 댓글이 **어느 콘텐츠에 달렸는지**(`processed/`의 id, 예: `script-01`)를 확인한다. 파일 이름이나 내용에 없으면 사용자에게 묻는다.
- 사용자 본인의 콘텐츠에 달린 댓글만 다룬다. 타인 콘텐츠의 댓글이면 멈추고 확인한다 (규칙 3).

## 1. 작성자 정보 제거 (저장 전에 반드시)
- 지운다: 작성자 이름, 닉네임, 아이디, 채널명, 프로필 링크·이미지, 프로필 관련 컬럼 전체.
- 본문 속 개인정보도 지운다 또는 `[삭제]`로 가린다: `@멘션`, 다른 사람의 실명·닉네임, 이메일, 전화번호, 개인 SNS 링크.
- 사용자의 답글은 댓글로 취급하지 않고 제외한다.
- 위 처리 후 남은 텍스트에서 다시 한 번 `@`, 이메일, 전화번호 패턴을 검사한다. 남아 있으면 업로드하지 않는다.

## 2. 반응 유형 분류
한 댓글에 하나의 유형만 붙인다. 애매한 댓글은 추측하지 말고 모아서 사용자에게 묻는다.
- `공감·칭찬`: 도움이 됐다, 감사하다, 좋다
- `질문`: 방법이나 이유를 묻는다
- `요청`: 다음에 다뤄 달라, 자료를 달라
- `정보·경험공유`: 자신이 해 본 경험이나 추가 정보를 준다
- `비판·불만`: 틀렸다, 아쉽다, 불편하다
- `스팸·기타`: 광고, 무관한 내용 (업로드하지 않는다)

## 3. 태깅과 표
각 댓글 문서의 필수 태그 6개를 채운다 (`CLAUDE.md`).
- `format`: `댓글`, `category`: 부모 콘텐츠의 카테고리, `target_audience`: 부모 콘텐츠와 동일
- `performance_grade`: 부모 콘텐츠의 등급, `published_at`: 댓글 작성일이 있으면 그 날짜, 없으면 `null`
- `key_message`: 댓글 내용을 한 문장으로 요약 (개인정보 없이)
- 추가 필드: `reaction_type`(위 분류), `parent_id`(부모 콘텐츠 id), `body`(정제된 본문)
- 결과는 **표로 먼저 보여준다** (id, 반응 유형, 요약, 삭제한 정보 종류와 건수). 사용자가 확인하기 전에는 저장하지 않는다.
- 작성일이 없는 댓글이 많으면 그 상태로 올릴지 묻는다. 기본은 업로드 보류이며, 허용할 때만 `--allow-missing published_at`.

## 4. 저장·업로드
1. `processed/comment-<부모id>-NN.json`으로 저장한다 (댓글 1개 = 문서 1개, `id`는 `comment-<부모id>-NN`).
2. `node scripts/upload.mjs --id <id>`로 dry-run 검증한다 (작성자 관련 필드, 이메일·전화번호·`@아이디`·프로필 주소가 있으면 거부된다). 여러 건이면 id를 하나씩 반복한다.
3. **검수 에이전트 호출 (필수)**: `--commit` 전에 반드시 `data-checker` 에이전트(Agent 도구, `subagent_type: "data-checker"`)를 호출한다. 프롬프트에 이번에 올릴 댓글 문서 id 전체와 "댓글 문서이므로 작성자 정보를 특히 엄격하게 볼 것"을 적는다.
   - `판정: 업로드 중단`이면 **댓글은 한 건도 올리지 않는다.** 문제가 된 문서와 이유를 한글로 전하고, 해당 댓글을 다시 정제(작성자 정보 삭제)하거나 제외한 뒤 검수를 다시 돌린다. 이 검수는 사용자가 요청해도 건너뛰지 않는다 (규칙 2).
   - "확인 필요" 항목(호칭, 자기소개 등)은 사용자에게 보여주고 답을 받는다.
4. 검수를 통과하고 사용자가 확인하면 `node --env-file=.env scripts/upload.mjs --id <id> --commit`. 대상은 Firestore `contents_input`이다. 키 파일(`keys/`)의 내용은 읽지 않는다. 경로는 `.env`에 있다.

## 5. 기록
`reports/ingest-log.md` 맨 아래에 추가한다: 날짜, 부모 id, 댓글 수, 반응 유형별 건수, 제외 건수(스팸·답글), 개인정보 제거 건수, 검수 결과(통과/중단과 사유), 업로드 결과. **기록에도 작성자 정보를 쓰지 않는다.**

## 금지
- 작성자 정보를 `processed/`, Firestore, 리포트, 채팅 요약 어디에도 남기지 않는다.
- `raw/comments/` 원본을 수정하거나 커밋하지 않는다.
- 사용자 확인 없이 `--commit` 하지 않는다.
