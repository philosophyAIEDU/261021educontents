# /fix-transcript — 대본 용어 교정

작업 폴더: 이 프로젝트 폴더(저장소를 내려받은 폴더). **`raw/`는 수정하지 않는다.** 교정은 `processed/<id>.json`의 `body`에만 적용한다.

## 용어집
같은 폴더의 `glossary.md`를 먼저 읽는다. 확정된 교정 규칙(오인식 → 올바른 표기)이 들어 있다. 새로 확정한 규칙은 **사용자 확인을 받은 뒤** 용어집에 추가한다.

## 절차
1. **대상 정하기**: 사용자가 준 id(또는 제목). 없으면 `processed/`의 대본 목록(`format: 유튜브 대본`)을 보여주고 묻는다.
2. **후보 찾기**: 대본을 읽고 (a) 용어집에 있는 오인식, (b) 문맥상 제품명·고유명사가 깨진 곳을 찾는다. 사용자가 직접 준 교정("A를 B로")도 포함한다.
3. **확실도 구분**
   - 확실: 다른 곳에서 올바른 표기가 확인되거나 용어집에 있는 것 → 고친다.
   - 불확실: 문맥으로 정할 수 없는 것 → **고치지 않고** 줄 번호·원문과 함께 목록으로 보고한다.
4. **변경 미리보기**: "줄 번호: 이전 → 이후" 형식으로 보여주고 확인받는다. 치환은 오탐이 없도록 좌우 문맥을 함께 본다 (예: "올라와 있습니다"의 "올라와"는 바꾸지 않는다). 줄바꿈으로 끊긴 표현도 확인한다.
5. **적용**: 확인 후 `processed/<id>.json`의 `body`를 수정하고 `body_note`에 "자막 용어 교정" 사실을 남긴다. 파이썬으로 처리할 때는 `PYTHONUTF8=1`을 켜고 출력에 특수문자를 쓰지 않는다 (Windows 콘솔 인코딩 오류 방지).
6. **다시 올리기**: 이미 업로드된 문서면 `node scripts/upload.mjs --id <id>`로 dry-run 후 확인받아 `--commit`으로 덮어쓴다 (`--commit`은 `node --env-file=.env scripts/upload.mjs ...`로 실행).
7. **기록**: `reports/ingest-log.md`에 id, 교정 줄 수, 미수정 목록, 재업로드 여부를 추가한다.

## 금지
- 의미를 바꾸는 윤문·요약·문장 다듬기는 하지 않는다. 용어와 명백한 인식 오류만 고친다.
- 불확실한 곳을 추측해서 고치지 않는다.
