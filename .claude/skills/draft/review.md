# 초고 공통 절차 (준비 → 근거 → 저장 → 검수 → Output 저장 → 보고)

`/draft`와 `/auto`가 따른다. (이 파일은 스킬이 아니라 `/draft`의 참고 문서다.)

## 1. 준비 (초고를 쓰기 전에 반드시)
1. `CLAUDE.md`의 "초고 작성 (Output)" 섹션(규칙 4~6)을 읽는다.
2. `voice.md`(말투, 특히 7절 금칙어)와 `structure.md`(전개 패턴)를 끝까지 읽는다. **둘 중 하나라도 "빈 템플릿"이면 멈추고** "먼저 `/analyze-style`로 내 말투를 분석해야 한다"고 알린다. 지어내서 쓰지 않는다.
3. `brand.md`에서 브랜드 이름·타깃을 읽는다 (인사말·호칭에 쓴다. 단 말투는 `voice.md`가 우선).
4. 오늘 날짜는 `date +%Y-%m-%d`로 얻는다.

## 2. 근거 자료 (지어내지 않기)
- 사실·예시·수치는 `processed/*.json`의 본문과 태그에서만 가져온다 (성과 등급 '상' 우선, 같은 카테고리·주제). 사용자가 실제로 만든 것·화면·경험을 우선한다.
- 자료에 없는 수치, 기능, 요금, 출시일은 쓰지 않는다. 꼭 필요하면 `[확인 필요: ...]`로 표시한다 (규칙 5).
- 댓글·문의 문서는 **어떤 질문이 많은지 패턴**으로만 참고한다. 원문 문장이나 특정인이 떠오르는 사례를 쓰지 않는다 (규칙 4).
- 쓴 뒤 `voice.md` 금칙어와 이모지가 남아 있지 않은지 스스로 한 번 훑는다 (규칙 6).

## 3. 저장 형식
경로: `drafts/<폴더>/<날짜>_<주제슬러그>.md` (`<폴더>`: `thread` / `newsletter` / `script` / `blog`, `/auto`는 `weekly/<날짜>/`).
- 슬러그: 주제에서 `\ / : * ? " < > |`를 빼고 공백은 `-`로, 40자 이내.
- 같은 이름이 있으면 덮어쓰지 말고 `-2`, `-3`을 붙인다.

```
# <주제> — <채널> 초고

- 작성일: YYYY-MM-DD
- 채널: 스레드 | 뉴스레터 | 유튜브 대본 | 블로그 글
- 상태: 초고 (내가 20% 손질한 뒤 발행)
- 근거 자료: script-04, post-02 (사용한 processed 문서 id)

## 초고
(본문)

## 적용한 규칙
- 말투: (적용한 voice.md 규칙 2~4개)
- 구조: (적용한 structure.md 패턴, 예: 훅 유형 B, 결과 먼저 → 의미)
- 참고한 콘텐츠: (id와 이유)

## 검수 메모
(검수 중)
```

## 4. 검수 (저장 직후, 필수)
1. **한 번의 응답에서 두 에이전트를 동시에** 부른다 (Agent 도구). 파일이 여러 개면 파일마다 둘 다 부른다.
   - `subagent_type: "voice-checker"` — 프롬프트: 초고 파일 경로와 채널
   - `subagent_type: "risk-checker"` — 프롬프트: 초고 파일 경로와 채널
2. 보고서 처리
   - **반드시 고칠 것**: risk-checker의 "반드시 고쳐야 함"과 voice-checker의 "금칙어 사용"은 **본문을 직접 고치고** 해당 에이전트를 다시 불러 확인한다 (최대 2회). 그래도 남으면 검수 메모에 "미해결"로 적는다.
   - **나머지 제안**(말투 어긋남, 평준화, 확인 필요)은 본문에 반영하지 않고 검수 메모로 남긴다. 20%의 손질은 사용자 몫이다.
3. `## 검수 메모`를 채운다.
```
## 검수 메모
- voice-checker: 통과 | 수정 권장 | 수정 필요 (최종)
- risk-checker: 통과 | 수정 권장 | 수정 필요 (최종)
- 자동으로 고친 것: (무엇을 어떻게, 없으면 "없음")
- 남은 수정 제안 (voice):
  - "<문장>" → 제안: "<문장>"
- 남은 확인 필요 (risk):
  - ...
- 미해결: 없음
```
4. 에이전트 호출이 실패하면 검수 메모에 `검수 실패: <이유>`라고 적는다. 검수 없이 통과한 것처럼 쓰지 않는다.

## 5. Contents Output 자동 저장 (검수 직후, 필수)
초고가 나오면 관리자 페이지(Contents Output)에 자동으로 올린다. 별도 확인은 받지 않는다.
1. `node --env-file=.env scripts/save-output.mjs --draft <초고 경로> --commit` (`.env`·`keys/` 내용은 읽지 않는다)
   - 같은 초고를 다시 저장하면 새 문서가 쌓이지 않고 덮어쓴다.
   - 검수 메모가 `(검수 중)`이거나 미해결 항목이 있으면 스크립트가 거부한다. 그때는 저장하지 않고 보고에 이유를 적는다.
   - `.env`가 없어 실패하면 초고는 그대로 두고 "Firebase 설정 후 `/draft save <경로>`로 올릴 수 있다"고 알린다.
2. Output에는 `## 초고` 본문만 올라간다 (검수 판정 두 줄은 `meta`로).
3. `reports/ingest-log.md`에 날짜, 초고 제목·채널, 참고 id, 저장 결과를 한 줄 추가한다.

## 6. 보고 (채팅, 짧게)
- 저장한 파일 경로, 사용한 훅·구조 한 줄
- 검수 판정 2개, 자동으로 고친 것, 먼저 볼 곳 1~3개
- Output 저장 결과 한 줄 (저장/갱신/거부 이유). 실패했으면 저장된 것처럼 쓰지 않는다.
- 초고 전문을 채팅에 다시 붙이지 않는다 (파일과 관리자 페이지에 있다).

## 자동 실행(질문 금지) 모드
`/auto`처럼 자동으로 부르는 경우 질문하지 않는다. 판단이 필요하면 안전한 쪽(쓰지 않음, `[확인 필요]` 표시)을 고르고 기록한다. `voice.md`·`structure.md`는 어떤 경우에도 수정하지 않는다.
