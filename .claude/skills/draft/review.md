# 결과물 공통 절차 (준비 → 근거 → 저장 → 검수 → 결과물 저장 → 보고)

`/draft`와 `/auto`가 따른다. (이 파일은 스킬이 아니라 `/draft`의 참고 문서다.)

## 1. 준비 (초고를 쓰기 전에 반드시)
1. `CLAUDE.md`의 "결과물 작성 (Output)" 섹션(규칙 4~6)을 읽는다.
2. `voice.md`(말투, 특히 금칙어 절), `structure.md`(전개 패턴), `knowledge-map.md`(지식 지도)를 끝까지 읽는다. **`voice.md`·`structure.md`가 "빈 템플릿"이면 멈추고** `/analyze-style`이, **`knowledge-map.md`가 "빈 템플릿"이면 멈추고** `/knowledge-map`이 먼저라고 알린다. 지어내서 쓰지 않는다.
3. `profile.md`에서 이름·담당 과목·학습자를 읽는다 (호칭·대상에 쓴다. 단 말투는 `voice.md`가 우선).
4. 오늘 날짜는 `date +%Y-%m-%d`로 얻는다.

## 2. 근거 자료 (지어내지 않기)
- 사실·정의·예시·수치·연구 결과는 `processed/*.json`의 본문과 태그, 그리고 `knowledge-map.md`(근거 id가 붙은 항목)에서만 가져온다. 같은 분야·같은 개념의 자료를 우선하고, 교수님이 실제로 쓴 사례·수업 장면·연구를 우선한다.
- **참고문헌·서지 정보(저자, 연도, 제목, 학술지, 쪽, DOI)는 근거 자료에 적힌 것만 그대로 옮긴다.** 기억나는 문헌이라도 덧붙이지 않는다. 필요하면 `[참고문헌 추가 필요: 무엇에 대한]`.
- 자료에 없는 수치, 연구 결과, 통계, 법·제도, 날짜는 쓰지 않는다. 꼭 필요하면 `[출처 확인 필요: ...]`로 표시한다 (규칙 5).
- 교수님의 관찰("제 수업에서는")은 관찰로 쓴다. "연구에 따르면"으로 바꾸지 않는다. 연구 결과는 원문의 조건·한계를 같이 쓴다.
- 학생 질문 문서는 **어떤 질문이 많은지, 어떤 오개념이 있는지 패턴**으로만 참고한다. 원문 문장이나 특정 학생이 떠오르는 사례를 쓰지 않는다 (규칙 4).
- 쓴 뒤 `voice.md` 금칙어와 이모지가 남아 있지 않은지, `[ ]` 표시 없이 단정한 사실이 없는지 스스로 한 번 훑는다 (규칙 5, 6).

## 3. 저장 형식
경로: `drafts/<폴더>/<날짜>_<주제슬러그>.md` (`<폴더>`: `lesson` / `handout` / `quiz` / `column` / `blog` / `script` / `book` / `paper`, `/auto`는 `weekly/<날짜>/`).
- 슬러그: 주제에서 `\ / : * ? " < > |`를 빼고 공백은 `-`로, 40자 이내.
- 같은 이름이 있으면 덮어쓰지 말고 `-2`, `-3`을 붙인다.

```
# <주제> — <종류> 초고

- 작성일: YYYY-MM-DD
- 종류: 강의안 | 학습자료 | 평가문항 | 칼럼 | 블로그 | 영상대본 | 교재 | 논문
- 대상: (학습자)
- 상태: 초고 (교수님이 사실 확인과 20% 손질을 한 뒤 사용)
- 근거 자료: lecture-04, paper-02 (사용한 processed 문서 id)

## 초고
(본문)

## 적용한 규칙
- 말투: (적용한 voice.md 규칙 2~4개)
- 구조: (적용한 structure.md 패턴, 예: 도입 유형 C — 오개념을 먼저 꺼낸다)
- 지식 지도: (쓴 개념·틀·사례와 그 근거 id)
- 참고한 자료: (id와 이유)

## 근거 표
| 초고의 사실·정의·인용 | 근거 |
|---|---|
| (문장 요약) | lecture-04 / 지식 지도 1절 / [출처 확인 필요] |

## 검수 메모
(검수 중)
```

## 4. 검수 (저장 직후, 필수)
1. **한 번의 응답에서 두 에이전트를 동시에** 부른다 (Agent 도구). 파일이 여러 개면 파일마다 둘 다 부른다.
   - `subagent_type: "voice-checker"` — 프롬프트: 초고 파일 경로와 종류
   - `subagent_type: "risk-checker"` — 프롬프트: 초고 파일 경로와 종류 (평가문항이면 "정답 근거를 문항마다 확인할 것")
2. 보고서 처리
   - **반드시 고칠 것**: risk-checker의 "반드시 고쳐야 함"(지어낸 인용, 근거 없는 연구 결과, 정답 근거 없음, 학생 노출, 효과 약속)과 voice-checker의 "금칙어 사용"은 **본문을 직접 고치고** 해당 에이전트를 다시 불러 확인한다 (최대 2회). 그래도 남으면 검수 메모에 "미해결"로 적는다.
   - **나머지 제안**(말투 어긋남, 평준화, 확인 필요)은 본문에 반영하지 않고 검수 메모로 남긴다. 20%의 손질은 교수님 몫이다.
3. `## 검수 메모`를 채운다.
```
## 검수 메모
- voice-checker: 통과 | 수정 권장 | 수정 필요 (최종)
- risk-checker: 통과 | 수정 권장 | 수정 필요 (최종)
- 자동으로 고친 것: (무엇을 어떻게, 없으면 "없음")
- 남은 수정 제안 (voice):
  - "<문장>" → 제안: "<문장>"
- 남은 확인 필요 (risk):
  - ...
- 교수님이 꼭 확인할 것: (`[출처 확인 필요]`·`[참고문헌 추가 필요]`·정답 등 개수와 위치)
- 미해결: 없음
```
4. 에이전트 호출이 실패하면 검수 메모에 `검수 실패: <이유>`라고 적는다. 검수 없이 통과한 것처럼 쓰지 않는다.

## 5. 결과물 자동 저장 (검수 직후, 필수)
초고가 나오면 관리자 페이지(결과물 탭)에 자동으로 올린다. 별도 확인은 받지 않는다. (관리자 전용 보관이며 학생이나 외부에 공개되지 않는다.)
1. `node --env-file=.env scripts/save-output.mjs --draft <초고 경로> --commit` (`.env`·`keys/` 내용은 읽지 않는다)
   - 같은 초고를 다시 저장하면 새 문서가 쌓이지 않고 덮어쓴다.
   - 검수 메모가 `(검수 중)`이거나 미해결 항목이 있으면 스크립트가 거부한다. 그때는 저장하지 않고 보고에 이유를 적는다.
   - `.env`가 없어 실패하면 초고는 그대로 두고 "Firebase 설정 후 `/draft save <경로>`로 올릴 수 있다"고 알린다.
2. 결과물에는 `## 초고` 본문만 올라간다 (검수 판정 두 줄은 `meta`로).
3. `reports/ingest-log.md`에 날짜, 초고 제목·종류, 근거 id, 저장 결과를 한 줄 추가한다.

## 6. 보고 (채팅, 짧게)
- 저장한 파일 경로, 쓴 구조·지식 지도 항목 한 줄
- 검수 판정 2개, 자동으로 고친 것, **교수님이 꼭 확인할 곳** 1~3개 (`[출처 확인 필요]`, 평가문항 정답 등)
- 결과물 저장 결과 한 줄 (저장/갱신/거부 이유). 실패했으면 저장된 것처럼 쓰지 않는다.
- 초고 전문을 채팅에 다시 붙이지 않는다 (파일과 관리자 페이지에 있다).

## 자동 실행(질문 금지) 모드
`/auto`처럼 자동으로 부르는 경우 질문하지 않는다. 판단이 필요하면 안전한 쪽(쓰지 않음, `[확인 필요]` 표시)을 고르고 기록한다. `voice.md`·`structure.md`·`knowledge-map.md`는 어떤 경우에도 수정하지 않는다.
