# /draft — 초고 쓰기 → 검수 → Contents Output 저장

작업 폴더: 이 프로젝트 폴더. 공통 절차(준비, 근거, 저장 형식, 검수, Output 저장)는 **같은 폴더의 `review.md`를 먼저 읽고 그대로 따른다.**

## 인자 읽기
`/draft [채널] <주제 한 줄 | 콘텐츠 id>` 또는 `/draft save <초고 경로>`

| 채널 말 | 채널 | 저장 폴더 |
|---|---|---|
| 스레드 | 스레드 | `drafts/thread/` |
| 뉴스레터 | 뉴스레터 | `drafts/newsletter/` |
| 대본, 유튜브 | 유튜브 대본 | `drafts/script/` |
| 블로그, 글 | 블로그 글 | `drafts/blog/` |

- 채널이 없으면 brand.md의 `기본 초고 채널`을 쓴다.
- 주제가 없으면 그것만 묻는다. 뭘 쓸지 모르겠다고 하면 `/topic-ideas`를 권한다.
- 주제 자리에 `script-04`, `post-02`처럼 `processed/`의 id가 있으면 **재구성 모드**다 (아래).
- `save <경로>`면 "다시 올리기"로 바로 간다.

## 채널별 쓰는 법
공통: `voice.md`(말투·호칭·문장 길이·금칙어·채널별 차이)와 `structure.md`(훅 유형, 전개, 마무리)를 **그대로** 따른다. 아래는 그 파일이 비어 있는 부분을 채우는 기본값일 뿐이다. 이모지·과장·성과 약속은 쓰지 않는다 (규칙 5, 6).

- **스레드**: 버전 **3개**를 쓴다. 버전마다 `structure.md` 3절의 서로 다른 훅 유형으로 첫 글을 시작한다. 글 4~7개, 글 하나 500자 이하, 글마다 `1/N` 번호. 첫 글이 전부다(개념 설명으로 시작하지 않는다). 결과·경험 먼저 → 의미. 마지막 글은 행동 유도 하나. `### 버전 1 — 훅 유형 B`처럼 나눈다.
- **뉴스레터**: 제목 후보 3개(서로 다른 각도: 얻는 것 / 대상 / 구체적 결과) → `voice.md`의 인사말 → 본문(실습이면 번호 단계, 아니면 핵심 3~5가지) → **나의 생각**(발신자의 인격이 앞에 선다. 근거 자료에 있는 경험만, 없으면 `[내 경험을 여기에 넣어 주세요]`) → 다음 편 예고는 `[다음 편 주제: 직접 정해 주세요]` → `voice.md`의 끝인사.
- **유튜브 대본**: 제목 후보 3개 → 도입(30초 안: 하려는 일·결과·대상을 먼저) → 본문(결과·화면을 먼저 보여 주고 의미를 붙인다, 화면은 `[화면: 무엇]`, 근거 없는 화면은 `[실제 화면으로 채워 주세요]`) → 한계·조건 → 마무리(자료 안내 → `voice.md` 6절의 마무리 정형구). 기본 분량 7~10분(약 1,000~1,500어절), 짧은 주제는 짧게.
- **블로그 글**: 제목 후보 3개 → 첫 문단에 이 글로 얻는 것 → 소제목(`###`) 3~5개 → 정리. 검색으로 들어온 사람도 이해하도록 용어를 한 번씩 풀어 쓴다. `voice.md`에 블로그 특징이 있으면 그것을 따른다.

## 재구성 모드 (콘텐츠 id를 준 경우)
기존 콘텐츠 하나를 다른 채널에 맞게 **다시 짠다.** 요약이 아니다.
1. `processed/<id>.json`을 읽는다. 없으면 `/ingest`가 먼저라고 알린다. 제목 일부만 주면 후보를 보여 주고 고르게 한다.
2. 채널을 안 정했으면 원본과 다른 채널을 고른다 (대본이면 뉴스레터와 스레드 둘 다 써도 된다. 뉴스레터 → 스레드 순서).
3. **사실·수치는 원본에 있는 것만** 쓴다. 원본의 성과 수치(조회수 등)를 자랑하듯 넣지 않는다. 자막 오류로 의미가 불확실한 곳은 빼거나 `[확인 필요]`.
4. 스레드는 원본에서 가장 눈에 띄는 결과·장면 하나를 첫 글의 훅으로 삼고 **버전 하나**만 쓴다.
5. 메타의 근거 자료에 `원본: <id>`를 적고, `## 적용한 규칙`에 원본에서 살린 것과 버린 것을 한두 줄 적는다.

## 절차
1. `review.md` 1~2 (준비, 근거 자료)
2. 위 채널 규칙으로 초고를 쓴다.
3. `review.md` 3 (저장) → 4 (검수) → 5 (Output 저장) → 6 (보고). 스레드 보고에는 세 버전의 **첫 글만** 나란히 보여 준다.

## 다시 올리기 (`/draft save <경로>`)
사용자가 손질한 초고를 Output에 다시 올린다. 새로 쓰지 않는다.
1. 파일이 `review.md` 3의 형식인지 본다 (`## 초고`, `## 검수 메모`). 본문을 크게 고쳤으면 검수(`review.md` 4)를 다시 할지 묻는다.
2. `node scripts/save-output.mjs --draft <경로>`로 미리 검사 → 통과하면 `node --env-file=.env scripts/save-output.mjs --draft <경로> --commit`. 같은 초고는 같은 문서를 덮어쓴다 (새로 쌓이지 않는다).
3. 검수 메모에 미해결 항목이 있어 거부되면, 사용자에게 알리고 허락을 받은 경우에만 `--allow-unresolved`를 붙인다.

## 예시
- `/draft 스레드 유튜브 알고리즘보다 먼저 챙겨야 할 것`
- `/draft 대본 초보자가 AI로 첫 앱을 만드는 순서`
- `/draft 뉴스레터 script-04`
- `/draft save drafts/thread/2026-10-05_주제.md`
