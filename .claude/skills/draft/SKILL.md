# /draft — 결과물 초고 쓰기 → 검수 → 결과물 저장

작업 폴더: 이 프로젝트 폴더. 공통 절차(준비, 근거, 저장 형식, 검수, 결과물 저장)는 **같은 폴더의 `review.md`를 먼저 읽고 그대로 따른다.**

## 인자 읽기
`/draft [종류] [대상:학습자] <주제 한 줄 | 자료 id | id,id,id>` 또는 `/draft save <초고 경로>`

| 종류 말 | 종류 | 저장 폴더 |
|---|---|---|
| 강의안, 수업안, 강의계획 | 강의안 | `drafts/lesson/` |
| 학습자료, 핸드아웃, 요약노트, 읽기자료, FAQ | 학습자료 | `drafts/handout/` |
| 평가문항, 퀴즈, 시험문제, 문항 | 평가문항 | `drafts/quiz/` |
| 칼럼, 기고, 에세이 | 칼럼 | `drafts/column/` |
| 블로그, 뉴스레터, 글 | 블로그 | `drafts/blog/` |
| 영상, 대본, 유튜브, 강연 원고 | 영상대본 | `drafts/script/` |
| 교재, 책, 챕터 | 교재 | `drafts/book/` |
| 논문, 학술 원고, 투고 원고 | 논문 | `drafts/paper/` |

- 종류가 없으면 profile.md의 `기본 결과물 종류`를 쓴다.
- `대상:현직교사`처럼 학습자를 주면 그 학습자에 맞춘다. 없으면 근거 자료의 `target_audience`, 그것도 없으면 profile.md의 `주요 학습자` 첫 번째.
- 주제가 없으면 그것만 묻는다. 뭘 쓸지 모르겠다고 하면 `/asset-ideas`를 권한다.
- 주제 자리에 `lecture-04`, `paper-02`처럼 `processed/`의 id가 있으면 **재활용 모드**, 쉼표로 여러 id면 **묶음 모드**다 (아래).
- `save <경로>`면 "다시 올리기"로 바로 간다.

## 종류별 쓰는 법
공통: `voice.md`(말투·호칭·문장 길이·금칙어·종류별 차이), `structure.md`(도입 유형, 전개, 확인 방식, 마무리), `knowledge-map.md`(개념 정의·틀·사례·관점)를 **그대로** 따른다. 개념은 지식 지도 1절의 **교수님 정의**로 설명하고, 예시는 3절의 **교수님 사례**를 먼저 쓴다. 아래는 그 파일이 비어 있는 부분을 채우는 기본값일 뿐이다. 이모지·과장·효과 약속·지어낸 인용은 쓰지 않는다 (규칙 5, 6).

- **강의안**: 과목·차시·대상·시간(기본 75분) → **학습 목표** 2~4개(행동 동사: 설명할 수 있다, 구분할 수 있다, 적용할 수 있다) → 선수 개념(지식 지도 6절) → 시간표 형식의 전개(도입 / 전개 1·2 / 활동 / 확인 / 정리, 각 분량과 교수자 활동·학습자 활동) → 슬라이드 개요(`[슬라이드 N] 제목 — 핵심 한 줄`) → 이해 확인 질문 2~3개(지식 지도 5절의 오개념을 겨냥) → 과제·다음 차시 연결. 교수님 자료에 없는 활동은 `[활동 아이디어 — 교수님 판단 필요]`로 표시한다.
- **학습자료**: 제목 → 이 자료로 알게 되는 것 3가지 → 핵심 개념 설명(교수님 정의 → 예시 → 흔한 오해 → 바로잡기) → 정리 표 또는 그림 설명 → 스스로 확인하기(문항 3개, 정답은 맨 끝) → 더 읽을 거리(**근거 자료에 있는 문헌만**, 없으면 `[참고문헌 추가 필요]`). FAQ 형식을 원하면 학생 질문 패턴(원문 아님)을 질문으로 다시 써서 Q&A로 만든다.
- **평가문항**: 문항마다 ① 측정하는 학습 목표 ② 유형(선다형·단답형·서술형·사례 적용형) ③ 난이도(하·중·상) ④ 문항 ⑤ 정답(서술형은 채점 기준과 모범 답안 요지) ⑥ **정답 근거: 자료 id와 해당 부분 요약** ⑦ 오답 선택지가 노리는 오개념. 기본 5문항, 암기형보다 적용·분석형 우선. 근거 자료로 정답을 확정할 수 없는 문항은 만들지 않는다.
- **칼럼**: 제목 후보 3개 → 첫 문단은 독자가 겪는 장면이나 질문(전문 용어 없이) → 교수님의 관점·연구가 말하는 것(원문의 조건·한계 포함) → 일상의 예 → 독자가 해 볼 수 있는 것 하나 → 맺음. 기본 2,000~3,000자. 연구를 인용할 때 "연구에 따르면"을 쓰려면 근거 자료 id가 있어야 한다.
- **블로그**: 제목 후보 3개 → `voice.md`의 인사말 → 첫 문단에 이 글로 얻는 것 → 소제목(`###`) 3~5개 → 정리. 검색으로 들어온 사람도 이해하도록 용어를 한 번씩 풀어 쓴다.
- **영상대본**: 제목 후보 3개 → 도입(30초 안: 오늘의 질문과 대상) → 본문(사례·장면을 먼저, 개념을 뒤에. 화면은 `[화면: 무엇]`, 근거 없는 화면은 `[실제 자료로 채워 주세요]`) → 한계·조건 → 마무리(`voice.md`의 수업 마무리 정형구). 기본 7~10분(약 1,000~1,500어절).
- **교재**: 장 제목 → 이 장의 학습 목표 → 도입 사례 → 절(`##`) 3~5개, 절마다 개념 → 예시 → 정리 상자 → 장 끝 생각해 볼 문제 3개 → 핵심 용어 목록(지식 지도 1절) → 참고문헌(근거 자료에 있는 것만, 나머지는 `[참고문헌 추가 필요]`). 글말(`voice.md` 7절의 논문·칼럼 문체)로 쓴다. 강의 녹취를 쓸 때 구어 표현을 글말로 바꾸되 교수님의 설명 순서와 비유는 살린다. 길면 절 단위로 나눠 파일 여러 개로 써도 된다 (`drafts/book/<날짜>_<장>-1.md`).
- **논문**: 제목 후보 3개 → 초록 → 서론(연구 질문과 필요성) → 이론적 배경 → 연구 방법 → 결과 → 논의 → 결론과 한계 → 참고문헌. 학술지에 맞는 글말(`voice.md` 7절의 논문·연구 문체)로 쓴다. 근거 자료가 연구 메모나 강의면 그것을 논문 구조로 펼친다. **근거 자료에 없는 데이터·표본·통계·결과는 만들지 않고** `[데이터 필요: 무엇]`으로 남긴다. 선행연구와 참고문헌은 근거 자료에 있는 것만 쓰고 나머지는 `[참고문헌 추가 필요: 무엇에 대한]`으로 남긴다. 근거 자료가 이미 낸 논문이면 문장만 바꿔 다시 쓰지 말고(중복 게재), 후속 연구 질문이나 다른 관점의 새 논문으로 짠 뒤 `[교수님 확인: <id>와 겹치는 범위]`를 남긴다. 공저 자료면 `coauthors_note`를 근거 표에 적는다. 본문 끝에 `[투고 전 확인: 학술지의 AI 활용 규정과 저자 표기]`를 남긴다.

## 재활용 모드 (자료 id 하나를 준 경우)
기존 자료 하나를 다른 종류·다른 학습자에 맞게 **다시 짠다.** 요약이 아니다.
1. `processed/<id>.json`을 읽는다. 없으면 `/ingest`가 먼저라고 알린다. 제목 일부만 주면 후보를 보여 주고 고르게 한다.
2. 종류를 안 정했으면 지식 지도 8절(재활용 지도)의 제안을 따른다. 없으면 원본과 다른 종류를 고른다 (강의 녹취 → 학습자료, 논문 → 칼럼).
3. **사실·수치·연구 결과는 원본에 있는 것만** 쓴다. 학습자가 바뀌면 용어와 예시를 바꾸되 주장의 범위는 바꾸지 않는다. 녹취 오류로 의미가 불확실한 곳은 빼거나 `[확인 필요]`.
4. 메타의 근거 자료에 `원본: <id>`를 적고, `## 적용한 규칙`에 원본에서 살린 것과 버린 것, 학습자에 맞춰 바꾼 것을 한두 줄 적는다.

## 묶음 모드 (여러 id를 준 경우)
여러 자료를 하나의 결과물로 엮는다 (예: 3~5주차 강의 → 교재 한 장).
1. 모든 id를 읽고, 지식 지도 6절(개념 연결)의 순서로 배열한다. 자료끼리 정의가 다르면(지식 지도의 "정의가 다름" 표시) 하나를 고르지 말고 `[교수님 확인: lecture-03과 lecture-05의 정의가 다름]`으로 남긴다.
2. 자료 사이에 빠진 연결(전환 문단)은 쓰되 새 사실을 넣지 않는다. 내용이 비는 곳은 `[이 부분은 자료에 없음 — 녹음·메모 필요]`로 표시한다.
3. 근거 자료 줄에 모든 id를 적는다.

## 절차
1. `review.md` 1~2 (준비, 근거 자료)
2. 위 종류 규칙으로 초고를 쓴다.
3. `review.md` 3 (저장) → 4 (검수) → 5 (결과물 저장) → 6 (보고).

## 다시 올리기 (`/draft save <경로>`)
교수님이 손질한 초고를 결과물에 다시 올린다. 새로 쓰지 않는다.
1. 파일이 `review.md` 3의 형식인지 본다 (`## 초고`, `## 검수 메모`). 본문을 크게 고쳤으면 검수(`review.md` 4)를 다시 할지 묻는다.
2. `node scripts/save-output.mjs --draft <경로>`로 미리 검사 → 통과하면 `node --env-file=.env scripts/save-output.mjs --draft <경로> --commit`. 같은 초고는 같은 문서를 덮어쓴다 (새로 쌓이지 않는다).
3. 검수 메모에 미해결 항목이 있어 거부되면, 사용자에게 알리고 허락을 받은 경우에만 `--allow-unresolved`를 붙인다.
4. 교수님이 고친 내용 중 앞으로도 적용할 것(정의, 말투, 순서)이 있으면 `knowledge-map.md`·`voice.md`·`structure.md`에 반영할지 묻는다 (CLAUDE.md "규칙 파일 수정 원칙").

## 예시
- `/draft 강의안 넣는 공부와 꺼내는 공부`
- `/draft 학습자료 대상:학부생 lecture-01`
- `/draft 평가문항 lecture-01`
- `/draft 칼럼 paper-02`
- `/draft 교재 lecture-03,lecture-04,lecture-05`
- `/draft 논문 paper-02,lecture-04`
- `/draft save drafts/lesson/2026-10-21_넣는-공부와-꺼내는-공부.md`
