# /start — 시작 안내와 현황

작업 폴더: 이 프로젝트 폴더. 사용자는 **입문자**다. 한국어로, 개발 용어 없이, **한 번에 한 단계만** 안내한다.

## 1. 상태 확인 (질문하기 전에 직접 본다)

먼저 `node scripts/setup-check.mjs`를 실행한다. 아래 표의 항목을 순서대로 점검해 ✅/⬜와 "다음 할 일"을 알려 준다 (`.env`·`keys/`는 존재와 파일 이름만 본다). 세션 시작 때 같은 결과가 자동으로 맥락에 들어와 있으면 그것을 써도 된다. Node.js가 없어 실행이 안 되면 1단계(Node.js 설치)부터 안내한다.

| 확인 | 방법 | 뜻 |
|---|---|---|
| 설치 | `scripts/node_modules` 폴더가 있는가 | 없으면 1단계 |
| 브랜드 | `brand.md` 맨 위에 "빈 템플릿"이 있는가, `브랜드 이름`·`사이트 주소`가 비었는가 | 비었으면 2단계 |
| Firebase | `.env` 파일이 **있는지만** 본다 (내용은 읽지 않는다), `keys/`의 `.json` **파일 이름만** 본다 | 없으면 3단계 |
| 관리자 페이지 | `admin/index.html`의 `firebaseConfig`에 `YOUR_`가 남았는가 | 남았으면 4단계 |
| 내 사이트 연결 | `site-repo/`(또는 brand.md의 `사이트 저장소 폴더`)에 `contents-admin.html`이 들어갔는가 | 없으면 5단계 |
| 콘텐츠 | `processed/*.json` 개수, `raw/`에 아직 처리하지 않은 파일 | 3편 미만이면 6단계 |
| 말투 | `voice.md` 맨 위에 "빈 템플릿"이 있는가 | 있으면 7단계 |
| 초고 | `drafts/` 아래 초고 파일 | 없으면 8단계 |

## 2. 단계별 안내 (지금 단계 하나만)

0. **처음 인사**: 사용자가 처음 묻는 것이면 "이 폴더는 내 콘텐츠를 모아 내 말투로 초고를 만들고, 내 사이트의 관리자 페이지에서 보게 해 줍니다. 세팅은 약 10단계이고 지금 N단계까지 됐습니다"처럼 한두 줄로 시작한다.
1. **설치**: 내가 대신 실행한다: `npm install --prefix scripts`. Node.js가 없다는 오류면 [nodejs.org](https://nodejs.org)에서 LTS 설치를 안내한다.
2. **브랜드 정보**: 아래 "3. 브랜드 질문"을 한다.
3. **Firebase 만들기**: 사용자가 **직접** 해야 한다. `TUTORIAL.md` 3~4단계를 한 화면씩 안내하고, 지금 화면에 무엇이 보이는지 물어본다. `.env`는 내가 `.env.example`을 복사해 만들어 줄 수 있지만 **값은 사용자가 직접** 채운다.
4. **관리자 페이지 설정**: Firebase 콘솔의 웹 앱 설정(`firebaseConfig`)을 붙여 달라고 한다 (이 값은 공개돼도 되는 값이다). 받은 값과 brand.md의 `브랜드 이름`을 `admin/index.html`의 `SITE_NAME`, `firebaseConfig`에 넣는다.
5. **내 사이트에 올리기**: `/site`를 권한다.
6. **콘텐츠 모으기**: 처음이면 `examples/`의 연습 대본으로 `/ingest`를 체험하게 한다. 그다음 내 콘텐츠 3~5편: 유튜브 링크, 내 사이트 글 주소, RSS, 또는 `raw/`에 파일 → `/ingest`.
7. **말투 분석**: `/analyze-style`.
8. **초고**: `/topic-ideas` → `/draft`. 익숙해지면 `/auto`.

모두 끝났으면 "준비 완료"라고 알리고 아래 4의 현황과 `/auto` 예약 실행(`/menu` 참고)을 소개한다.

## 3. 브랜드 질문 (brand.md 채우기)

**한 번에 한두 가지씩** 묻는다. 답을 받을 때마다 `brand.md`의 해당 줄(`- 항목: 값`)에 적고, 다 채우면 맨 위 "상태" 줄을 `채움 (YYYY-MM-DD)`로 바꾼다. 항목 이름은 바꾸지 않는다 (스크립트가 읽는다).

1. 브랜드(채널) 이름과 한 줄 소개
2. 누구를 위한 콘텐츠인가(주요 타깃), 주로 다루는 주제
3. 쓰는 채널 (유튜브 / 뉴스레터 / 스레드 / 블로그) → `운영 채널`, 그중 초고를 가장 자주 쓸 채널 → `기본 초고 채널`
4. **내 사이트 주소**와 **그 사이트의 GitHub 저장소 주소**
5. 유튜브 채널 주소(`https://www.youtube.com/@핸들`), 블로그·뉴스레터 RSS 주소, 사이트 말고 내 글이 올라가는 곳(`내 다른 주소`) — 없으면 비운다. RSS 주소를 모르면 사이트 주소 뒤에 `/rss.xml`, `/feed`, `/rss`를 붙여 열어 보고 제안한다.

함께 반영할 것:
- 주제·타깃은 `.claude/skills/taxonomy/taxonomy.md`에 "사용자 설명(아직 확정 전)"으로 적는다. `/ingest`가 태그를 고를 때 쓴다.
- 말투는 **직접 정하지 않는다.** `/analyze-style`이 실제 콘텐츠에서 뽑는다. 사용자가 "이 말은 절대 안 써요"라고 하면 `voice.md` 7절 금칙어에 추가한다.
- 성과등급 기준(조회수 몇 이상이 '상'인지)은 채널 규모에 따라 다르다. 기본값(100 / 1000)을 보여 주고 바꿀지 물어, 바꾸면 `CLAUDE.md`의 "성과등급 기준"을 고친다.

## 4. 현황 (콘텐츠가 1편 이상일 때 함께 보여 준다)
- `raw/`(하위 `comments/` 포함, `hold/` 제외)에서 `processed/*.json`의 `source_file`에 없는 파일 → "아직 안 올린 파일"
- `raw/hold/`의 파일과 `.hold.txt` 사유 → "보류된 파일"
- `processed/*.json` 표: id, 제목, 포맷, 카테고리, 성과등급, 조회수, 발행일, 비어 있는 태그
- 집계: 포맷별·카테고리별·성과등급별 편수, `drafts/`의 초고 수
- 수치는 파일 값을 그대로 옮기고 추정하지 않는다. 실제 Firebase 내용은 관리자 페이지에서 확인하라고 안내한다.

## 보고
확인 결과 한두 줄 → 다음 할 일 **하나** (사용자가 할 일인지, 내가 대신 할 수 있는 일인지 구분) → 필요하면 현황 표. 긴 목록을 한꺼번에 쏟아내지 않는다.

## 금지
- `.env`, `keys/`의 내용을 읽거나 출력하지 않는다. 사용자가 키나 `.env` 내용을 채팅에 붙이려 하면 말린다. 이미 붙였다면 그 키를 폐기하고 새로 발급하도록 안내한다.
- brand.md에 비밀번호·API 키·서비스 계정 키를 적지 않는다.
