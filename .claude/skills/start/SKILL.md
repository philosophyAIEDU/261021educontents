# /start — 처음부터 끝까지 순서대로 안내

작업 폴더: 이 프로젝트 폴더. 사용자는 **교수·교육자이고 입문자**다. 사이트를 이미 만들고 Firebase도 연동했다. 한국어 존댓말로, 개발 용어 없이 안내한다. **교수님이 다음에 뭘 할지 고민하지 않게 Claude가 이끈다.**

## 목표 (첫 답에서 한 번 쉽게 말한다)
```
교수님 자료 ──▶ Input (지식 창고) ──▶ 지식 지도 ──▶ Output (결과물: 논문·강의안·학습자료 등 초고)
```
Input과 Output은 교수님 사이트의 관리자 페이지에서 봅니다. 수업과 연구 자료를 넣을수록 교수님의 지식이 찾아 쓰고 다시 만들 수 있는 자산으로 쌓입니다.

## 1. 상태 확인 (질문하기 전에 직접 본다)
`node scripts/setup-check.mjs`를 실행해 점검표와 "다음 할 일"을 얻는다 (`.env`·`keys/`는 존재와 파일 이름만 본다). 세션 시작 때 같은 결과가 맥락에 들어와 있으면 첫 답에서는 그것을 써도 된다. Node.js가 없어 실행이 안 되면 1단계부터 안내한다. 끝난 단계는 다시 시키지 않는다.

## 2. 안내하는 방법
- **첫 답**: 위 목표를 두세 줄로 → "전체 N단계 중 M단계까지 됐습니다" → 지금 단계의 카드 하나.
- **한 번에 한 단계만** 보여 준다. 전체 목록을 쏟아내지 않는다.
- **단계가 끝나면 바로 다음으로 간다.** 끝났다고 하시면 직접 확인하고(`setup-check` 다시 실행, 확인할 수 없는 것은 교수님 말씀대로) "○단계 완료" 한 줄과 함께 다음 카드를 보여 준다. "다음은 뭘까요?"라고 묻게 만들지 않는다.
- **Claude가 할 수 있는 단계는 묻지 말고 바로 한다.** 끝나면 결과만 알린다. 단 금지 사항과 `/site` 푸시처럼 스킬이 확인을 요구하는 일은 확인을 받는다.
- 교수님 화면은 볼 수 없다. 막히면 "화면에 보이는 글자를 그대로 적어 주세요"라고 하고, 오류 문구를 읽어 하나씩 푼다.
- 잘 안 되는 단계가 있어도 탓하지 않고, 지금 위치와 해결 방법만 말한다.

### 단계 카드 (교수님이 하실 일이 있을 때 이 모양으로)
```
**[M/N단계] 제목**

왜 하나요: (한 줄)

이렇게 하세요:
1. ...
2. ...

끝나면 "..."라고 말씀해 주세요.
```

## 3. 단계별 내용 (`setup-check`의 순서와 같다)

**① 준비**
1. **Node.js**: 교수님이 nodejs.org에서 LTS를 설치하고 터미널과 Claude를 다시 켠다.
2. **프로그램 설치**: 내가 바로 `npm install --prefix scripts`를 실행한다.
3. **프로필**: 이름과 전공 분야만 묻고 profile.md에 적는다. 나머지는 첫 초고 뒤에 묻는다 (아래 4절).

**② 이미 만든 사이트·Firebase에 연결** (프로젝트를 새로 만들지 않는다. 이 폴더로 사이트를 만드셨다면 끝난 항목은 건너뛴다)

4. **키 넣기**: 왜: "Claude가 자료와 초고를 교수님 Firebase에 저장할 때 쓰는 열쇠입니다." `FIREBASE_KEY_GUIDE.md` 1단계를 카드로 안내하고, "키 받았어요"라고 하면 내가 `node scripts/connect-firebase.mjs`를 실행한다. 폴더를 만들거나 파일 이름을 바꾸라고 하지 않는다. 다운로드 폴더에 없으면 `--file <경로>`로 지정한다. 안내 문구(`[...]`)가 나오면 쉬운 말로 전하고 해결한다. 이 명령이 끝나면 5단계(`.env`)도 함께 끝난다.
5. **`.env`**: 4단계에서 함께 만들어진다. 따로 시키지 않는다.
6. **관리자 페이지 설정**: 왜: "Input과 Output을 보는 화면을 교수님 Firebase와 잇습니다." `https://console.firebase.google.com/project/_/settings/general`을 열고 프로젝트를 고른 뒤, 아래쪽 **내 앱**에서 웹 앱의 `firebaseConfig`를 복사해 붙여 달라고 한다 (공개돼도 되는 값이다). 웹 앱이 없으면 `</>` 아이콘으로 등록하게 한다. 받은 값과 profile.md의 `이름`을 `admin/index.html`의 `firebaseConfig`, `SITE_NAME`에 넣는다.
7. **관리자 페이지 로그인**: 사이트 주소를 묻고 profile.md의 `사이트 주소`에 적는다. `<사이트 주소>/knowledge-admin.html`을 열어 Google 로그인을 해 보시게 한다. **지식 창고** 탭이 보이면 profile.md의 `관리자 페이지 확인`에 오늘 날짜를 적는다.
   - 페이지가 없으면(404) 사이트에 아직 안 들어간 것이다: `/site`로 넣는다. **이미 있는 사이트를 `/create-site`로 다시 올리지 않는다.** GitHub로 배포하지 않는 사이트면 `관리자 페이지 보는 곳: 내 컴퓨터`로 바꾸고 `npx serve admin`을 실행해 `http://localhost:3000`에서 로그인하게 한다.
   - 로그인 후 접근 권한 오류면 `TUTORIAL.md`의 문제 해결을 따른다 (관리자 이메일, Firestore 규칙).
   - 로컬에 쌓인 자료와 초고가 있으면 이때 올린다: `node --env-file=.env scripts/upload.mjs --all --commit`(미리 검사 먼저, 확인 후), 초고는 `/draft save <경로>`.

**③ 지식 자산화**

8. **자료 넣기 (Input)**: 왜: "교수님 지식의 재료입니다." 내가 `raw/` 폴더를 열어 드린다 (Windows `explorer raw`, Mac `open raw`). 슬라이드·한글·워드·PDF·녹취 텍스트를 끌어다 넣게 한다. 한 과목의 연속된 차시 3~5편이 가장 좋고, 논문은 직접 쓴 원고나 연구 메모가 좋다고 알린다. 직접 만든 자료만 넣고, 성적·출석부·상담 기록은 넣지 않는다고 한 줄 알린다. 자료가 지금 없으면 `examples/`의 연습 강의를 `raw/`로 복사해 준다. 끝나면 "자료 넣었어요"라고 말씀해 달라고 한다.
9. **첫 초고 받기 (Output)**: "자료 넣었어요"라고 하면 묻지 않고 바로 `/make`를 한다. 시작할 때 시간이 조금 걸린다고 알린다. 끝나면 관리자 페이지의 **지식 창고**(Input)와 **결과물**(Output) 탭을 열어 보시게 하고, 사실·인용·정답은 교수님이 직접 확인해야 하는 초고라고 알린다.

**④ 자동화**

10. **매주 자동 실행**: 왜: "수업이 끝나고 `raw/`에 자료만 넣어 두면 초고까지 저절로 쌓입니다." 언제 돌릴지 묻고 `.claude/skills/auto/SKILL.md`의 "예약 실행"대로 안내한다. 정한 시간을 profile.md의 `매주 자동 실행`에 적는다. 몇 번 더 직접 써 본 뒤 하겠다고 하면 `나중에`로 적는다.

**다 끝나면** 이렇게 마무리한다: "세팅이 끝났습니다. 앞으로는 새 자료를 `raw/`에 넣고 `/make`라고만 하시면 됩니다." 그다음 권할 것 하나만 고른다: `/make`가 처음 만든 `voice.md`·`knowledge-map.md` 초안 읽고 고치기, 나머지 프로필 채우기, 학생 질문(`/ingest-questions`), 여러 자료를 묶는 결과물(`/asset-ideas` → `/draft`).

## 4. 프로필 질문 (profile.md 채우기)

**한 번에 한두 가지씩** 묻는다. 답을 받을 때마다 `profile.md`의 해당 줄(`- 항목: 값`)에 적고, 다 채우면 맨 위 "상태" 줄을 `채움 (YYYY-MM-DD)`로 바꾼다. 항목 이름은 바꾸지 않는다 (스크립트가 읽는다).

1. 이름(관리자 페이지와 결과물에 쓸 표기)과 소속
2. 전공 분야와 세부 연구 주제
3. 담당 과목(과목명과 대상 학년)과 주요 학습자(학부생, 대학원생, 현직 교사, 일반 시민 등)
4. 지식을 펼치는 채널 (수업 / 유튜브 / 칼럼 / 블로그 / 뉴스레터 / 책) → `운영 채널`, 가장 자주 만들 결과물 → `기본 결과물 종류` (강의안 / 학습자료 / 평가문항 / 칼럼 / 블로그 / 영상대본 / 교재 / 논문)
5. 관리자 페이지를 **내 사이트**에서 볼지, **내 컴퓨터**에서만 볼지 → `관리자 페이지 보는 곳`. 사이트면 **사이트 주소**, 관리자 페이지를 넣어야 하면 **그 사이트의 GitHub 저장소 주소**
6. 유튜브 채널 주소(`https://www.youtube.com/@핸들`), 블로그·뉴스레터 RSS 주소, 사이트 말고 내 글이 올라가는 곳(`내 다른 주소`: 브런치, 학교 교수 소개 페이지, 언론사 칼럼 기사 주소) — 없으면 비운다. RSS 주소를 모르면 사이트 주소 뒤에 `/rss.xml`, `/feed`, `/rss`를 붙여 열어 보고 제안한다.

함께 반영할 것:
- 전공 분야·세부 주제·학습자는 `.claude/skills/taxonomy/taxonomy.md`에 "교수님 설명(아직 확정 전)"으로 적는다. `/ingest`가 태그를 고를 때 쓴다.
- 담당 과목은 `/knowledge-map` 7절(자산 공백)의 기준이 된다.
- 말투는 **직접 정하지 않는다.** `/analyze-style`이 실제 자료에서 뽑는다. 교수님이 "이 말은 절대 안 써요"라고 하면 `voice.md` 금칙어 절에 추가한다.
- 반응 등급은 선택이다. 유튜브 강의가 있으면 조회수 기본 기준(100 / 1000)을 보여 주고 바꿀지 묻는다. 강의평가 점수 등으로 등급을 매기고 싶어 하면 기준("몇 점 이상이 상인가요?")을 받아 `CLAUDE.md`의 반응 등급 문단에 적는다.

## 5. 현황 (자료가 1편 이상일 때 함께 보여 준다)
- `raw/`(하위 `questions/` 포함, `hold/` 제외)에서 아직 `processed/`에 없는 파일 → "아직 안 올린 파일" (문서 파일은 `.meta.json`의 `original_file`로 변환 여부를 본다)
- `raw/hold/`의 파일과 `.hold.txt` 사유 → "보류된 파일"
- `processed/*.json` 표: id, 제목, 종류, 분야, 지식 유형, 학습자, 강의·작성일, 비어 있는 태그
- 집계: 종류별·분야별·지식 유형별 편수, `drafts/`의 초고 수
- 수치는 파일 값을 그대로 옮기고 추정하지 않는다. 실제 Firebase 내용은 관리자 페이지에서 확인하라고 안내한다.

## 금지
- `.env`, `keys/`의 내용을 읽거나 출력하지 않는다. 사용자가 키나 `.env` 내용을 채팅에 붙이려 하면 말린다. 이미 붙였다면 그 키를 폐기하고 새로 발급하도록 안내한다.
- profile.md에 비밀번호·API 키·서비스 계정 키·학생 정보를 적지 않는다.
