# /takedown — 업로드된 콘텐츠 삭제

작업 폴더: 이 프로젝트 폴더(저장소를 내려받은 폴더). 삭제는 Firestore에서 지워지며 복구되지 않는다.

## 절차
1. **대상 확인**: 사용자가 준 id(또는 제목)를 `processed/*.json`에서 찾아 id, 제목/`source_file`, 포맷, 업로드 여부를 보여준다. 후보가 여러 개면 고르게 한다.
2. **사유 묻기**: 규칙 위반(2: 작성자 정보, 3: 타인·유료 콘텐츠) / 중복 / 오류 / 기타. 사유는 기록에 남긴다. 규칙 2 위반이면 같은 정보가 `processed/`, `reports/`에도 남아 있는지 함께 점검한다.
3. **dry-run**: `node scripts/delete.mjs --id <id>` — 삭제 대상만 출력하고 아무것도 지우지 않는다.
4. **명시적 확인**: "정말 삭제할까요? 삭제 대상: <id> (Firestore contents_input)"로 다시 묻고, 사용자가 확인한 뒤에만 진행한다.
5. **삭제**: `node --env-file=.env scripts/delete.mjs --id <id> --commit` (키 파일(`keys/`)의 내용은 읽지 않는다. 경로는 `.env`에 있다).
6. **로컬 정리**: `processed/<id>.json`을 `processed/_removed/`로 옮긴다. 완전 삭제는 사용자가 따로 요청할 때만 한다 (`raw/` 원본은 건드리지 않는다). 규칙 2 위반으로 작성자 정보가 든 파일은 이동 대신 삭제 여부를 묻는다.
7. **기록**: `reports/ingest-log.md`에 날짜, id, 사유, 삭제 결과를 추가한다 (작성자 정보는 쓰지 않는다).

## 금지
- 확인 없이 `--commit` 하지 않는다. 여러 건을 한꺼번에 지울 때도 id를 나열해 확인받는다.
- `--all` 같은 일괄 삭제는 지원하지 않는다.
