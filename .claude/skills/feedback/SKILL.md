# /feedback — 반응 기록 (수치 갱신 + 사용 후 기록)

작업 폴더: 이 프로젝트 폴더. **대화형**이다. 필요한 것만 짧게 묻는다. 요청을 보고 A 또는 B를 고른다 (애매하면 묻는다).

## 등급 기준
`CLAUDE.md`의 반응 등급 문단을 따른다 (기본: 유튜브 강의 조회수 100 미만 하 / 100 이상 1000 미만 중 / 1000 이상 상). 반응 등급(`reception_grade`)은 **선택 태그**다.
**기준이 없는 지표(강의평가 점수, 질문 수, 칼럼 공유 수 등)로 등급을 만들지 않는다.** 그런 지표를 등급에 쓰려면 먼저 "몇 이상이 상인가요?"를 묻고, 답을 받으면 `CLAUDE.md`에 적는다. 기준이 없으면 수치만 기록한다.

## A. 자료의 반응 수치 갱신
1. **대상 찾기**: 준 id나 제목을 `processed/*.json`(`title`, `source_file`, `key_message`)에서 찾는다. 여러 개면 고르게 하고, 없으면 `/ingest`가 먼저라고 알린다. "전체 갱신"이면 `youtube_url`이 있는 문서 전부.
2. **수치 얻기**: 사용자가 준 값을 우선 쓴다. 유튜브 조회수는 `youtube_url`이 있고 `.env`에 `YOUTUBE_API_KEY`가 있을 때 `node --env-file=.env scripts/enrich.mjs --id <id>`(전체는 `--all`)로 가져온다. 키가 없으면 유튜브 스튜디오의 조회수를 알려 달라고 한다. 강의평가는 **과목 전체의 평균 점수만** 받는다 (학생별 점수·원자료는 받지 않는다, 규칙 2).
3. **변경 표**: id, 제목, 이전 → 새 수치·등급을 보여 주고 확인받는다. 확인 전에는 저장하지 않는다.
4. **저장·업로드**: `processed/<id>.json`의 `views`, `views_fetched_at`, `rating`(강의평가 평균, 예: `{"value": 4.5, "scale": 5, "term": "2026-1"}`), `tags.reception_grade`, `grade_source`만 고친다 → `node scripts/upload.mjs --id <id>`로 미리 검사 → 확인 후 `node --env-file=.env scripts/upload.mjs --id <id> --commit`.
5. 학생 질문 문서(`parent_id`가 같은 것)는 반응 등급을 따로 매기지 않는다.
6. `reports/ingest-log.md`에 날짜, id, 이전→이후, 수치 출처(사용자/API), 업로드 결과를 적는다.

## B. 결과물 사용 후 기록 (수업 1~2주 뒤, 발행 7~14일 뒤)
초고를 만들고 끝나면 자산이 자라지 않는다. "실제로 얼마나 고쳤는지"와 학생·독자 반응을 다시 넣어야 `voice.md`·`structure.md`·`knowledge-map.md`를 고칠 근거가 생긴다.
1. **어떤 초고인가**: `drafts/`의 최근 초고를 보여 주고 고르게 한다 (초고 없이 만든 자료면 "초고 없음").
2. **사용 정보**: 수업에 쓴 날(과목·주차) 또는 발행일·링크.
3. **얼마나 고쳤나**: 거의 그대로(20% 이하) / 일부(20~50%) / 대폭(50% 초과) / 새로 씀. 최종본 텍스트를 주면 초고와 비교해 대략의 수정 비율을 계산한다 (대략치라고 밝힌다). 많이 고쳤으면 어디를 왜 고쳤는지 1~3가지 묻는다 (특히 **사실·정의를 고쳤다면** 그것은 지식 지도 문제일 수 있다).
4. **반응**: 종류별 핵심 지표 하나만 받는다. `CLAUDE.md`에 합의된 지표가 없으면 제안(강의안·학습자료: 수업 중 질문 수나 이해 확인 정답률(반 전체) / 평가문항: 문항별 정답률(반 전체) / 칼럼·블로그: 조회수·공유 수 / 영상: 조회수)을 보여 주고 고르게 한 뒤 `CLAUDE.md`에 적는다. **학생 개인별 결과는 받지 않는다.**
5. **평가문항이면**: 정답률이 아주 낮거나 높은 문항, 학생들이 많이 고른 오답을 묻는다. 많이 고른 오답은 오개념 후보로 `reports/monthly/inbox.md`에 적는다 (지식 지도 5절 갱신 재료).
6. **저장**: `reports/feedback/<날짜>_<슬러그>.json`으로 저장하고 `node scripts/save-output.mjs --file <경로>` → 통과하면 `node --env-file=.env scripts/save-output.mjs --file <경로> --commit`. 관리자 페이지 결과물 탭에 "사용 기록"으로 보인다.
```
{ "title": "[사용 기록] 강의안 · <주제>", "type": "사용 기록",
  "sourceIds": ["<관련 processed id가 있으면>"],
  "body": "사용일, 수정 정도, 지표와 수치, 메모를 읽기 쉽게 요약",
  "meta": { "kind": "lesson", "draft_file": "drafts/lesson/...", "used_at": "YYYY-MM-DD", "course": "교육심리학 4주차",
            "edit_level": "일부 수정", "edit_ratio_estimate": 0.3,
            "metric": "이해 확인 정답률(반 전체)", "value": 0.72, "grade": "상|중|하|null", "days_after_use": 10 } }
```
7. **최종본을 지식 창고에도**: 교수님이 고친 최종본(강의안·칼럼)을 아직 올리지 않았다면 `/ingest`를 권한다 (다음 분석과 지식 지도의 재료가 된다).
8. **규칙으로 남길 피드백**: 3·5에서 나온 수정 이유 중 앞으로도 적용할 것은 `reports/monthly/inbox.md`에 날짜와 함께 한 줄씩 추가한다. `voice.md`·`structure.md`·`knowledge-map.md`는 여기서 고치지 않는다 (월간 리뷰와 지식 지도 갱신에서 교수님이 승인한다).

## 금지
- 수치를 지어내거나 추정해서 채우지 않는다. 모르면 비운다.
- 학생 개인별 점수·답안을 받거나 저장하지 않는다.
- 기준 없는 지표로 등급을 매기지 않는다. 사용자 확인 없이 `--commit` 하지 않는다.
- `.env`, `keys/`의 내용을 읽거나 출력하지 않는다.
