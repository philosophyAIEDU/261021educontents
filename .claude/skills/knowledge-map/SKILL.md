# /knowledge-map — 나의 지식 지도 만들기·갱신하기

작업 폴더: 이 프로젝트 폴더. 지식 지도는 교수님 지식 자산의 **목차이자 색인**이다. 결과물(`/draft`)은 이 지도를 근거로 쓰이므로, **근거 없는 항목은 한 줄도 넣지 않는다.**

## 실행 모드
- `/knowledge-map` (만들기): `knowledge-map.md`가 "빈 템플릿"일 때. 전체 자료로 처음 만든다.
- `/knowledge-map 갱신`: 이미 채워져 있을 때. 지도 맨 아래 `## 변경 이력`의 마지막 반영 이후 새로 올라간 자료만 읽고 **추가·수정안**을 만든다. 기존 항목은 교수님 승인 없이 바꾸지 않는다.
- 이미 채워져 있는데 인자 없이 부르면 갱신 모드로 진행한다고 알리고 진행한다.
- 자동 실행(`/auto`)에서는 이 스킬을 부르지 않는다 (지도는 대화 중에만 고친다).

## 절차 (만들기)
1. `CLAUDE.md`(규칙 3~5), `profile.md`(전공·세부 주제·담당 과목·학습자), `knowledge-map.md`를 읽는다.
2. `processed/*.json`을 모두 읽는다. 0개면 멈추고 `/ingest`를 권한다. 3개 미만이면 "표본이 작아 지도가 듬성듬성하다"고 한계에 적고 계속한다.
3. 자료마다 다음을 뽑는다. **반드시 `body`에 있는 내용만**, 항목마다 근거 id를 붙인다.
   - **개념**: 교수님이 정의하거나 설명한 용어. "나의 정의"는 교수님 표현을 살린 요약이고, 원문이 짧으면 큰따옴표로 인용한다. 교과서 정의를 보충하지 않는다.
   - **틀**: "저는 이걸 ○○라고 부릅니다", 단계·순서·체크리스트·2×2 같은 반복되는 설명 구조.
   - **사례·비유·실험**: 무엇을 설명하려고 쓴 것인지와 함께. 출처 종류를 구분한다 (수업 장면 / 교수님 연구 / 개인 경험 / 문헌 — 문헌이면 원문에 적힌 서지 그대로).
   - **관점·주장**: 교수님이 취하는 입장, 연구가 보여 주는 것. 원문의 조건·한계를 같이 적는다. 교수님의 수업 관찰을 일반 법칙처럼 바꾸지 않는다.
   - **학생 질문**(`format: 학생 질문`): `question_type`, `misconception`, `related_concept`를 주제별로 묶어 **건수만** 센다. 원문은 인용하지 않는다 (규칙 4).
4. `knowledge-map.md`의 1~8절을 채운다.
   - 같은 개념이 여러 자료에 나오면 한 줄로 합치고 근거 id를 모두 적는다. **자료마다 정의가 다르면** 합치지 말고 둘 다 적은 뒤 "정의가 자료마다 다름 — 확인 필요"로 표시한다.
   - 6절(개념 연결)은 자료 안에서 실제로 이어 설명한 순서만 적는다. Claude가 아는 학문적 위계를 덧붙이지 않는다.
   - 7절(자산 공백)은 `profile.md`의 담당 과목·세부 연구 주제와 올라간 자료를 비교해, 이름은 있는데 자료가 없는 영역을 적는다. 학문적으로 "빠졌다"고 판단하지 않는다. 공백은 "아직 기록 안 됨"이다.
   - 8절(재활용 지도)은 자료마다 바로 만들 수 있는 결과물 종류를 1~3개 적는다 (예: 강의 녹취 → 학습자료·평가문항, 논문 → 칼럼·강의안, 질문 모음 → FAQ 학습자료).
   - 근거가 없는 절은 템플릿 문구를 지우지 말고 "데이터 없음"으로 둔다.
5. 맨 위 "상태" 줄을 **"초안 v0 — 교수님 확인 전"**으로 바꾸고, "근거 자료와 한계"를 채우고, `## 변경 이력`에 `YYYY-MM-DD, 만들기, 반영한 자료 id 전체`를 적는다 (갱신 때 새 자료를 고르는 기준이다).
6. `reports/<오늘 날짜>_knowledge-map.md`에 읽은 id, 절별 항목 수, "정의가 다름" 항목, 공백 목록을 남긴다.
7. 채팅에는 짧게: 절별 항목 수, 교수님이 꼭 확인할 것 3가지("정의가 다름" 항목, 근거가 한 편뿐인 핵심 개념 등), 자산 공백 상위 3개, "직접 읽고 '저는 이렇게 정의하지 않아요'처럼 말씀해 주시면 반영합니다".

## 절차 (갱신)
1. 위 1을 한다. `## 변경 이력`에 적힌 id들을 모으고, 거기에 없는 `processed/` 문서만 고른다. 없으면 "새 자료 없음"으로 끝낸다.
2. 위 3을 새 자료에만 한다.
3. **수정안**을 만든다. 형식:
```
### 추가안 K-1 (1절 핵심 개념)
- 근거: lecture-07
- 추가: | 간격 효과 | "…" | … | … | lecture-07 |
### 수정안 K-2 (1절 '인출 연습')
- 근거: lecture-07이 lecture-01과 다르게 정의
- 변경 전: > …
- 변경 후: > …
```
4. 수정안을 하나씩 보여 주고 `AskUserQuestion`으로 "반영 / 보류 / 고쳐서 반영"을 받는다 (추가안은 여러 개를 한 번에 물어도 된다). 승인된 것만 `knowledge-map.md`에 반영하고 `## 변경 이력`에 `YYYY-MM-DD, 갱신, 반영 N건, 이번에 읽은 자료 id 전체`를 적는다 (보류한 수정안의 자료도 읽은 것으로 적고, 보류 항목은 리포트에 남긴다).
5. 교수님이 대화 중에 새 정의·사례·입장을 말해 주면: 그 말을 `raw/note-<날짜>-<주제>.txt`로 저장하고(`.meta.json`에 `{"source":"conversation","format_hint":"","title":"…","published_at":"<오늘>"}`), `/ingest`로 올린 뒤 그 id를 근거로 지도에 반영한다. 근거 id 없이 지도에 쓰지 않기 위해서다.

## 금지
- 근거 자료에 없는 개념·정의·사례·문헌을 넣지 않는다 (규칙 5). Claude가 아는 내용으로 빈칸을 채우지 않는다.
- 학생 질문 원문, 학생을 알아볼 수 있는 사례를 넣지 않는다 (규칙 4).
- 갱신 모드에서 승인 없이 기존 항목을 바꾸거나 지우지 않는다. 자동 실행에서 이 파일을 고치지 않는다.
