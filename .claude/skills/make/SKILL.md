# /make — 자료 넣고 초고 받기 (한 번에)

작업 폴더: 이 프로젝트 폴더. 교수님이 할 일은 **`raw/`에 파일을 넣고 `/make`라고 하는 것뿐**이다. 나머지(변환 → 정리·태깅 → 지식 창고 → 말투·지식 지도 → 초고 → 검수 → 저장)는 이 스킬이 한다.

`/auto`와 같은 절차를 쓰지만, `/make`는 **교수님이 보고 있을 때** 부르는 것이다. 그래서 정말 판단이 필요한 것(학생 질문, 공저·출판본 의심)만 끝에 모아 한 번에 묻는다. 중간에 하나씩 멈추지 않는다.

## 인자
- 없음: `raw/`의 새 자료를 모두 처리하고 만들 초고를 `scripts/plan.mjs` 목록대로 만든다.
- 자료 id(`lecture-03`): 그 자료로 만들 결과물만.
- 결과물 종류(`평가문항`, `강의안` …): 이번 실행에서 그 종류만 (목록에서 그 종류만 고른다).
- `목록만`: 2단계까지 하고 만들 초고 목록만 보여 준다.

## 절차

### 0. 준비
- `date +%Y-%m-%d`로 오늘 날짜를 얻고 `CLAUDE.md`, `profile.md`를 읽는다.
- `profile.md`의 `이름`·`전공 분야`가 비었으면 **그 두 가지만** 묻고 적는다 (나머지 프로필은 나중에 `/start`).
- `.env`가 있는지만 본다(내용은 읽지 않는다). 없으면 **로컬 모드**: 지식 창고·결과물은 이 컴퓨터(`processed/`, `drafts/`)에만 저장하고 Firebase 업로드는 하지 않는다. 실패로 다루지 않는다.

### 1. 모으기 (자료 → 지식 창고)
1. `node scripts/extract.mjs --auto --limit 5` — `raw/`의 문서 파일을 텍스트로 바꾸고, profile.md에 적힌 유튜브·RSS·사이트 저장소의 새 자료도 가져온다. PDF를 바로 읽지 못했다는 메시지가 나오면 `.claude/skills/ingest/SKILL.md` 0단계대로 Claude가 직접 읽는다.
2. `.claude/skills/ingest/SKILL.md`의 **자동 모드**로 정리·태깅·검수한다. 단 `/make`에서는:
   - 태그가 애매한 자료(분야·학습자·날짜)는 보류하지 말고 **가장 그럴듯한 값으로 정하고 "추정" 표시**(`tag_guess: ["created_at"]`처럼)를 남긴 뒤 계속한다. 끝에 추정한 것을 표로 보여 준다. (날짜는 파일 수정일을 추정값으로 써도 된다.)
   - 규칙 3 의심(공저, 출판본, 타인 자료)과 학생 정보를 확실히 지울 수 없는 자료는 **보류**한다 (`raw/hold/`). 이것은 추정으로 넘기지 않는다.
   - 로컬 모드면 업로드 명령은 dry-run(`node scripts/upload.mjs --id <id>`)까지만 하고, `processed/<id>.json`을 남긴다.
3. `raw/questions/`에 새 학생 질문 파일이 있으면 처리하지 말고 끝에 "`/ingest-questions`로 올릴까요?"라고 묻는다 (규칙 2: 신원 정보 제거를 교수님이 확인해야 한다).

### 2. 기준 파일 준비 (처음 한 번)
- `voice.md` 또는 `structure.md`가 "빈 템플릿"이면 `.claude/skills/analyze-style/SKILL.md` 절차로 **초안 v0**을 만든다.
- `knowledge-map.md`가 "빈 템플릿"이면 `.claude/skills/knowledge-map/SKILL.md`의 **만들기** 절차로 초안 v0을 만든다.
- 이미 채워진 파일은 **고치지 않는다.** 이번에 새로 들어온 자료는 끝에 "지식 지도에 반영할까요? (`/knowledge-map 갱신`)"으로 묻는다.
- 자료가 1~2편뿐이어도 진행하되, 초안에 "표본이 매우 작아 참고용"이라고 적는다.

### 3. 만들 초고 정하기
- `node scripts/plan.mjs --json` (인자에 자료 id가 있으면 `--id <id>`)으로 목록을 받는다. 자료마다 만들 결과물은 `scripts/schema.mjs`의 `DEFAULT_OUTPUTS`이고, `profile.md`의 `자동으로 만들 결과물`이 있으면 그 종류만이다. 이미 초고가 있는 조합은 목록에 나오지 않는다.
- 인자에 결과물 종류가 있으면 그 종류만 남긴다.
- 목록이 비면 "새로 만들 초고가 없습니다"와 함께 `/asset-ideas`(여러 자료를 묶는 결과물 제안)를 권하고 끝낸다.
- `목록만`이면 목록을 표로 보여 주고 끝낸다.

### 4. 초고 쓰기 → 검수 → 저장
목록의 항목마다 `.claude/skills/draft/SKILL.md`의 해당 종류 규칙과 `review.md`의 절차를 따른다.
- 항목의 `sources`가 하나면 draft의 **재활용 모드**, 여러 개(`학생 질문 FAQ`, `오개념 평가문항`, `재활용 + 오개념`)면 **묶음 모드**로 쓴다. 오개념 학생 질문이 근거에 있으면 평가문항의 오답 선택지가 그 오개념을 겨냥하게 한다. 학생 질문은 패턴으로만 쓰고 원문을 옮기지 않는다 (규칙 4).
- 대상 학습자는 항목의 `target`.
- 저장: `drafts/<folder>/<날짜>_<주제슬러그>.md` (`review.md` 3의 형식, 메타의 `- 종류:`와 `- 근거 자료:` 줄을 반드시 쓴다. 다음 실행에서 `plan.mjs`가 이 줄로 "이미 만든 것"을 안다).
- 검수: 초고마다 `voice-checker`와 `risk-checker`를 부른다. 초고가 여러 개면 **한 응답에서 여러 개를 동시에** 부른다. "반드시 고쳐야 함"은 고치고 다시 확인한다 (`review.md` 4).
- 저장: `.env`가 있으면 `review.md` 5대로 결과물(knowledge_output)에도 저장한다. 로컬 모드면 `node scripts/save-output.mjs --draft <경로>`(dry-run)로 형식만 확인하고 "Firebase를 설정하면 `/draft save <경로>`로 한 번에 올릴 수 있다"고 기록한다.
- 교재처럼 아주 긴 결과물은 목록에 없다 (`/draft 교재 …`로 교수님과 함께 쓴다).

### 5. 보고 (채팅, 짧게)
```
## /make 결과 (YYYY-MM-DD)
- 모은 자료: 새 N편 (슬라이드 N, 한글·워드 N, PDF N, 녹취 N) · 보류 N
- 기준 파일: voice.md·structure.md·knowledge-map.md — 이번에 초안 만듦 / 이미 있음
| # | 결과물 | 근거 자료 | 파일 | 검수(말투/정확성) | 꼭 확인할 곳 |
|---|---|---|---|---|---|
- 저장 위치: drafts/ (관리자 페이지 결과물 탭: 저장됨 / 로컬 모드라 저장 안 함)
```
그다음 **교수님께 확인받을 것**을 한 번에 묻는다 (해당하는 것만, 많으면 중요한 3개):
- 태그를 추정한 자료 (표: id, 추정한 태그, 추정값)
- 보류한 자료와 이유 (공저·출판본 등)
- 새 학생 질문 파일 → `/ingest-questions`
- 이번에 처음 만든 `voice.md`·`knowledge-map.md` 초안 → "열어 보시고 안 맞는 부분을 말씀해 주세요"
- 초고의 `[출처 확인 필요]`·평가문항 정답은 교수님이 직접 확인해야 한다는 한 줄

또 `reports/make.md` **맨 위**에 같은 요약을 남긴다 (파일이 없으면 `# /make 기록 (최신이 맨 위)`로 만든다).

## 금지
- 학생 질문을 자동으로 올리지 않는다. 학생 이름·학번을 어디에도 남기지 않는다 (규칙 2).
- 공저·출판본·타인 자료로 의심되는 것을 추정으로 넘기지 않는다 (규칙 3).
- 근거 자료에 없는 사실·인용을 쓰지 않는다 (규칙 5).
- 이미 채워진 `voice.md`·`structure.md`·`knowledge-map.md`를 고치지 않는다 (빈 템플릿을 처음 채우는 것만 한다).
- 초고를 배포(학생 공지, LMS, 언론사, 사이트 게시)하지 않는다. `.env`·`keys/` 내용을 읽지 않는다.
