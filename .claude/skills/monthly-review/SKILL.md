# /monthly-review — 월간·학기 돌아보기와 규칙 수정안

작업 폴더: 이 프로젝트 폴더.

## 실행 모드
- `/monthly-review` (기본): 분석 → 수정안을 변경 전/후로 보여 줌 → **항목별로 승인을 받고** 승인된 것만 반영.
- `/monthly-review prep` (자동 실행용): 분석과 수정안 저장까지만 한다. **질문하지 않는다. `voice.md`, `structure.md`, `knowledge-map.md`를 절대 수정하지 않는다.** 승인은 교수님이 나중에 대화에서 기본 모드로 한다.
- 기간: 인자에 `YYYY-MM`이 있으면 그 달, `YYYY-1학기`/`YYYY-2학기`면 3~6월/9~12월(학교 일정이 다르면 교수님이 준 기간), 없으면 지난달 (`date`로 오늘을 확인).

## 절차
1. **읽기**: `CLAUDE.md`(결과물 규칙과 수정 원칙), `voice.md`, `structure.md`, `knowledge-map.md`, `reports/monthly/inbox.md`(있으면), `reports/feedback/*.json`(대상 기간), `reports/ingest-log.md`.
2. **대상**: `processed/*.json` 중 `created_at`이 대상 기간인 것, 그리고 대상 기간의 사용 기록(`reports/feedback/`).
3. **돌아보기** (표로):
   - **결과물 사용 기록**: 종류별로 수정 비율이 컸던 것과 작았던 것. 많이 고친 이유(inbox, 사용 기록 메모)를 묶는다. → 주로 `voice.md`·`structure.md` 수정안의 근거
   - **사실·정의를 고친 기록**: 교수님이 초고의 정의·사례를 고친 것 → `knowledge-map.md` 수정안의 근거
   - **반응 비교**(수치가 있을 때만): 반응 상위 3개 vs 하위 3개의 도입 유형, 길이, 주제, 마무리 방식. 대상이 6개 미만이면 **표본이 부족하다**고 경고하고 위쪽 절반과 아래쪽 절반으로 나눈다. 2개 미만이면 비교하지 않는다.
   - **학생 질문**: 대상 기간의 질문을 유형별·개념별로 건수만 센다 (원문 인용 금지, 규칙 4). 평가문항 사용 기록의 "많이 고른 오답"도 오개념 후보로 합친다.
   - 차이를 "관찰"로 쓰고 **인과로 단정하지 않는다.**
4. **수정안**: `voice.md`, `structure.md`, `knowledge-map.md`에 대해 각각 항목별로 만든다. 변경하지 않아도 되면 "변경 없음"이라고 쓴다.
```
### 수정안 S-1 (structure.md 3절)
- 근거: (어떤 자료·사용 기록의 어떤 차이, inbox 항목)
- 변경 전: > (현재 문장)
- 변경 후: > (제안 문장)
- 위험: (표본 크기, 반대 사례)
```
   - id 앞글자: `V-`(voice), `S-`(structure), `K-`(knowledge-map).
   - 근거가 표본 1~2개뿐인 수정은 "근거 약함"이라고 표시한다.
   - 금칙어 추가·삭제, 말투 변경, **개념 정의 변경**처럼 교수님다움이 바뀔 수 있는 수정은 특히 신중하게, 반드시 근거를 붙인다. 지식 지도 수정안의 근거는 `processed/`의 id여야 한다 (대화로 들은 것은 `/knowledge-map` 5단계처럼 먼저 자료로 올린다).
5. **저장**: `reports/monthly/<기간>.md`(예: `2026-10.md`, `2026-2학기.md`)에 모드, 대상 기간, 데이터 한계, 돌아보기 표, 수정안 전체(각 항목 상태: `미승인`)를 저장한다. 같은 파일이 있으면 덮어쓰지 말고 `-2`를 붙인다.
6. **승인(기본 모드에서만)**: 수정안을 하나씩 보여 주고 `AskUserQuestion`으로 "승인 / 보류 / 수정해서 승인"을 받는다. 승인된 항목만 해당 파일에 반영하고, 각 파일 맨 아래 `## 변경 이력`에 `YYYY-MM-DD, 수정안 ID, 한 줄 요약`을 추가한다. 리포트의 항목 상태를 `승인`/`보류`로 바꾼다. 반영한 `inbox.md` 항목은 처리했다고 표시한다.
7. **prep 모드**는 6단계를 건너뛰고 "승인은 `/monthly-review`로 대화에서 진행하세요"라고 리포트 맨 위에 적는다.
8. **학기 모드 덤**: 기간이 학기면 리포트 끝에 "이번 학기에 새로 쌓인 자산" 요약(종류별 자료 수, 지식 지도에 새로 들어간 개념·사례 수, 만든 결과물 수)과 "다음 학기 전에 해 둘 것"(지식 지도 7절 공백 중 담당 과목과 관련된 것)을 덧붙인다. 수치는 파일에서 센 값만 쓴다.
9. **마무리 보고**: 저장 경로, 돌아보기 요약, 수정안 개수와 (기본 모드라면) 반영한 개수.

## 금지
- prep 모드나 자동 실행에서 `voice.md`, `structure.md`, `knowledge-map.md`를 수정하지 않는다.
- 승인받지 않은 수정안을 반영하지 않는다.
- 표본이 작은 관찰을 확정 사실처럼 쓰지 않는다. 학생 질문 원문을 인용하지 않는다.
