# /auto — 자료 모으기부터 초고까지 자동 실행 (질문 없음)

작업 폴더: 이 프로젝트 폴더. **사용자에게 질문하지 않는다.** 아무도 보지 않을 때 예약 실행되므로, 질문하면 거기서 멈춘다. 판단이 필요한 것은 기록만 하고 가능한 데까지 진행한다. 교수님이 지켜볼 때는 `/make`가 같은 일을 하고 끝에 확인할 것을 묻는다.

## 범위
- `/auto` : 0 → 1 → 2 → 3 → 4 → 5
- `/auto 수집만` : 0 → 1 → 5
- `/auto 초고만` : 0 → 2 → 3 → 4 → 5

## 절차
`.claude/skills/make/SKILL.md`의 0~4단계를 그대로 하되, 아래만 다르다.

0. **준비**: `date +%Y-%m-%d`, `date +%H%M`. `profile.md`의 `이름`·`전공 분야`가 비어 있어도 묻지 않는다 (태그는 자료에서 추정하고 기록한다). `.env`가 없으면 로컬 모드 (`/make` 0단계).
1. **모으기**: `/make` 1단계와 같다. profile.md의 `사이트 저장소 폴더`가 있으면 먼저 `git -C site-repo pull`(실패해도 계속). 태그 추정·보류 규칙도 같다. `raw/questions/`는 처리하지 않고 "학생 질문 파일 있음"만 기록한다.
2. **기준 파일**: `/make` 2단계와 같다. 빈 템플릿인 `voice.md`·`structure.md`·`knowledge-map.md`는 초안 v0을 만든다. **이미 채워진 파일은 고치지 않는다.** 새 자료가 지식 지도에 아직 없으면 "`/knowledge-map 갱신` 필요"로 기록한다.
3. **목록**: `node scripts/plan.mjs --json`. 개수는 `profile.md`의 `한 번에 만들 초고 수`(없으면 6). 남은 것은 다음 실행에서 만든다.
4. **초고**: `/make` 4단계와 같다. 저장 경로만 `drafts/weekly/<날짜>/NN_<슬러그>.md` (같은 날짜 폴더가 있으면 `<날짜>-<HHMM>`). 메타의 `- 종류:`·`- 근거 자료:` 줄을 반드시 쓴다. 검수 에이전트는 한 응답에서 여러 개를 동시에 부른다. 에이전트가 실패하면 `검수 실패: 이유`를 적고 다음으로 간다.
5. **기록과 보고**: `reports/auto.md` **맨 위**(제목 줄 바로 아래)에 추가한다. 파일이 없으면 `# 자동 실행 기록 (최신이 맨 위)`로 만든다.
```
## YYYY-MM-DD HH:MM /auto
- 모은 자료: 새 N편 (문서 파일 N, 유튜브 N, RSS N, 사이트 저장소 N) · 보류 N · 실패 N
- 모드: Firebase 저장 / 로컬 모드(.env 없음)
- 기준 파일: 이번에 초안 만든 것 (없으면 "없음")
### 초고
| # | 결과물 | 근거 자료 | 파일 | voice | risk | 저장 | 교수님이 꼭 확인할 곳 |
|---|---|---|---|---|---|---|---|
### 교수님이 할 일
- 태그를 추정한 자료 확인, 보류 자료 결정, 학생 질문 파일(`/ingest-questions`), 새로 만든 기준 파일 초안 읽기, `/knowledge-map 갱신`, 초고의 사실·정답 확인과 20% 손질 (해당하는 것만. 없으면 "없음")
### 실패·건너뜀
- (없으면 "없음")
```
   채팅에는 위 요약을 짧게 보여 주고 "초고는 drafts/weekly/<날짜>/(그리고 관리자 페이지 결과물 탭)에 있습니다"로 끝낸다. 질문으로 끝내지 않는다.

## 금지
- 이미 채워진 `voice.md`, `structure.md`, `knowledge-map.md`를 수정하지 않는다. 고치는 것은 `/monthly-review`와 `/knowledge-map 갱신`에서 교수님이 승인한다.
- 초고를 배포(학생 공지, LMS 업로드, 언론사 송고, 사이트 게시)하지 않는다. 결과물 저장은 관리자 전용 보관이다.
- 학생 질문(`raw/questions/`)을 자동으로 올리지 않는다.
- 삭제(`/takedown`), 사이트 저장소 푸시, `--allow-missing`, `--allow-unresolved`를 하지 않는다.
- `.env`, `keys/`의 내용을 읽지 않는다. 근거 없는 사실·인용을 쓰지 않는다 (규칙 5).

## 예약 실행 (사용자에게 안내할 때)
- **Claude Code 데스크톱 앱**: 예약 작업(Scheduled tasks)에 이 프로젝트 폴더와 프롬프트 `/auto`를 등록하고 요일·시간을 정한다 (예: 매주 월요일 오전 8시, 또는 수업 다음 날). 컴퓨터가 켜져 있어야 한다.
- **터미널**: 프로젝트 폴더에서 `claude -p "/auto" --permission-mode acceptEdits`. 이것을 Windows 작업 스케줄러나 Mac/Linux `cron`에 등록한다. 필요한 명령 권한은 `.claude/settings.json`에 미리 허용돼 있다.
- 처음에는 예약하지 말고 `/make`를 직접 두세 번 해 보고 결과가 괜찮으면 등록하기를 권한다.
- 학기 중에는 "수업이 끝나면 그 주 슬라이드와 녹취 텍스트를 `raw/`에 넣어 두기"만 하면 된다고 안내한다.
