# /menu — 명령어 메뉴 (읽기 전용)

## 절차
1. `.claude/skills/*/SKILL.md`의 `name`을 읽어 실제 목록과 아래 표를 비교한다. 표에 없는 스킬은 맨 아래 "기타"로 덧붙여 보여 주고, 없어진 스킬은 "(현재 없음)"으로 표시한다. 어긋나면 이 파일을 고칠지 물어본다 (묻기 전에는 고치지 않는다).
2. 아래 표들을 보여 준다. 특정 명령을 물으면 그 `SKILL.md`를 읽어 쉽게 설명한다.

## 기본 명령 (이것만 알면 된다)

흐름: **① 내 사이트 + Firebase(`/create-site`) → ② 모으기(지식 창고) → 분석·지식 지도 → 결과물(`/make`) → 공개할 글은 관리자 페이지에서 "사이트에 게시"**.

| 명령어 | 하는 일 | 예시 |
|---|---|---|
| `/create-site` | **내 사이트를 새로 만들고 Firebase에 연동해 올린다** (`<ID>.web.app`, 관리자 페이지 포함). 내용을 고쳐 다시 올릴 때도 | `/create-site` `/create-site 다시 올리기` |
| `/make` | **raw/에 넣은 자료로 초고를 한 번에 뽑는다**: 정리 → (처음엔 말투·지식 지도 초안) → 자료별 초고(강의 녹취 → 학습자료·평가문항, 슬라이드 → 강의안·학습자료, 논문 → 칼럼·학습자료) → 검수 → 저장 | `/make` `/make lecture-03` `/make 평가문항` |
| `/start` | 지금 몇 단계인지 보고 다음 할 일 하나를 알려 준다. 교수 프로필(이름·전공·과목 등)을 채운다 | `/start` |
| `/site` | **이미 있는** 내 사이트(GitHub 배포)에 관리자 페이지만 넣는다 | `/site` |
| `/ingest` | 강의자료·녹취·논문·칼럼을 가져와 정리·태깅하고 **지식 창고**에 올린다 | `/ingest` (raw/에 파일을 넣고) `/ingest https://youtu.be/...` |
| `/analyze-style` | 내 말투(`voice.md`)와 잘 통한 수업·글의 전개(`structure.md`)를 채운다 (처음 한 번) | `/analyze-style` |
| `/knowledge-map` | 내 개념 정의·설명 틀·사례·관점·자산 공백을 **지식 지도**(`knowledge-map.md`)로 정리한다 | `/knowledge-map` `/knowledge-map 갱신` |
| `/asset-ideas` | 다음에 만들 결과물 후보 5개를 근거와 함께 제안한다 | `/asset-ideas` |
| `/draft` | 강의안·학습자료·평가문항·칼럼·블로그·영상대본·교재 초고를 쓰고, 검수한 뒤 **결과물**에 자동 저장한다 | `/draft 강의안 주제 한 줄` `/draft 칼럼 paper-02` |
| `/auto` | `/make`를 질문 없이 (예약 실행용) | `/auto` (매주 예약 실행 가능) |

## 가끔 쓰는 명령

| 명령어 | 하는 일 | 언제 |
|---|---|---|
| `/ingest-questions` | 학생 질문·강의평가 서술형에서 신원 정보를 지우고 질문 유형(개념·적용·오개념 등)으로 분류해 올린다 | 학기 중, 강의평가가 나왔을 때 |
| `/feedback` | 유튜브 조회수·강의평가 평균 갱신, 결과물을 수업·발행에 쓴 뒤 수정 정도와 반응 기록 | 수업 1~2주 뒤, 발행 7~14일 뒤 |
| `/monthly-review` | 한 달·한 학기를 돌아보고 `voice.md`·`structure.md`·`knowledge-map.md` 수정안을 만들어 승인한 것만 반영 | 매월 초, 학기 말 |
| `/draft save <파일>` | 손질한 초고를 결과물에 다시 올린다 | 초고를 고친 뒤 |
| (관리자 페이지) 사이트에 게시 | 결과물 탭에서 공개할 글을 골라 사이트의 '글'에 올린다 (교수님이 직접 누른다) | 칼럼·블로그를 손질한 뒤 |
| `/audit` | 키 유출·학생 정보·타인 저작물 점검 (읽기 전용) | GitHub에 올리기 전, 학기 말 |
| `/takedown` | 잘못 올린 자료를 Firebase에서 삭제 (확인 후) | 실수로 올렸을 때 |

## 익숙해지면 쓰는 명령

| 명령어 | 하는 일 |
|---|---|
| `/fix-transcript` | 자동 자막·녹음 전사의 전공 용어·학자 이름 오인식을 용어집 기준으로 고친다 |
| `/taxonomy` | 분야·학습자 태그 표기를 통일한다 |

## 자동으로 도는 검수 (직접 부를 필요 없음)

| 검수 | 하는 일 |
|---|---|
| `data-checker` | 올리기 직전: 필수 태그, 중복, 학생 신원 정보, 저작권 의심 |
| `voice-checker` | 초고 직후: 교수님 말투인지, 금칙어 |
| `risk-checker` | 초고 직후: 지어낸 인용·근거 없는 연구 결과, 평가문항 정답 근거, 효과 약속, 학생 노출 |

## 학기 루틴 (예시)

| 시점 | 할 일 |
|---|---|
| 처음 한 번 | `/create-site` (사이트 + Firebase 연동) |
| 학기 시작 전 | `/knowledge-map 갱신` → `/asset-ideas` → 이번 학기 강의안 `/draft 강의안 …` |
| 매주 수업 후 | 슬라이드·녹취 텍스트를 `raw/`에 넣기 → `/make` (또는 예약해 둔 `/auto`) → 초고 확인 |
| 학생 질문이 모이면 | `/ingest-questions` → 오개념 학습자료·평가문항 `/draft` |
| 수업·발행 후 | `/feedback` |
| 매월 초, 학기 말 | `/monthly-review` (학기 말은 `/monthly-review 2026-2학기`) |
| 헷갈릴 때 | `/start` |

예약 실행 방법은 `.claude/skills/auto/SKILL.md`의 "예약 실행"을 요약해 알려 준다. 자동 실행은 `voice.md`·`structure.md`·`knowledge-map.md`를 절대 바꾸지 않는다.
