# /ingest — 내 자료 가져오기 → 정리·태깅 → 지식 창고 업로드

작업 폴더: 이 프로젝트 폴더. 반드시 `CLAUDE.md`의 필수 태그·규칙 1~3을 따른다.

## 실행 모드
- `/ingest` (기본): 애매한 것은 묻고, 태그 표를 확인받은 뒤 올린다.
- `/ingest auto` (자동): 질문하지 않는다. 아래 "자동 모드"가 확인·질문 단계를 대신한다. `/auto`가 이 모드를 쓴다.
- 인자에 파일·링크가 있으면 0단계에서 먼저 가져온다.

## 0. 가져오기 (raw/에 텍스트 원본 만들기)
`scripts/extract.mjs`로 `raw/`에 `.txt`와 `.txt.meta.json`(제목, 날짜, 조회수, 원본 주소·파일)을 만든다. 스크립트는 **profile.md에 적힌 내 주소의 자료만** 가져오고(규칙 3), 이미 가져온 것은 건너뛴다.

| 사용자가 준 것 | 명령 |
|---|---|
| `raw/`에 넣은 문서 파일 (.pptx .docx .hwpx .pdf .srt .vtt) | `node scripts/extract.mjs --file raw/<파일>` (전부면 `--file raw`) |
| 다른 폴더의 파일 경로 | 먼저 `raw/`로 복사해 달라고 하거나 복사해 준 뒤 위와 같이 |
| 유튜브 강의 영상 링크 | `node scripts/extract.mjs --youtube <링크>` |
| 내 유튜브 채널 링크 ("최근 강의 가져와") | `node scripts/extract.mjs --youtube <채널 링크> --limit 5` |
| 내 사이트·블로그·칼럼 글 주소 | `node scripts/extract.mjs --url <주소>` |
| RSS 주소 ("블로그/뉴스레터 글 가져와") | `node scripts/extract.mjs --rss <RSS 주소> --limit 10` |
| "내 사이트 글 전부" (저장소에 마크다운 글이 있을 때) | `node scripts/extract.mjs --repo site-repo --limit 20` |
| raw/ 의 문서 + profile.md에 적힌 곳 모두 | `node scripts/extract.mjs --auto` |

- 여러 개를 가져올 때는 먼저 `--list`를 붙여 목록을 보여 주고 확인받는다 (자동 모드는 생략).
- `.pptx`는 슬라이드 글자와 **발표자 노트**를 함께 뽑는다. 노트에 교수님의 설명이 들어 있는 경우가 많으니 정제 때 살린다. 그림·도표 속 글자는 뽑히지 않는다고 알린다.
- **PDF를 바로 읽지 못했다**(pdftotext 없음)는 메시지가 나오면: Read 도구로 PDF를 직접 읽어 본문 텍스트를 `raw/file-<파일 이름 슬러그>-pdf.txt`로, 정보를 `raw/file-<…>-pdf.txt.meta.json`(`{"source":"file","format_hint":"","title":"…","original_file":"<원본 PDF 이름>"}`)으로 만든다. 20쪽이 넘으면 나눠 읽는다. 원본 PDF는 고치지 않는다. 스캔본이라 글자가 없으면 그렇다고 알린다.
- `.hwp`(옛 한글), `.ppt`, `.doc`: 오류 문구대로 새 형식(.hwpx, .pptx, .docx)이나 PDF로 저장해 달라고 안내한다.
- `내 주소가 아닙니다`: 교수님 본인 글인지 묻는다. 맞다면 그 주소를 profile.md `내 다른 주소`에 추가하고 다시 실행한다. 타인의 글이면 멈춘다.
- `yt-dlp 가 없습니다`: 오류 문구의 설치 방법을 안내한다. 설치가 어려우면 유튜브 스튜디오 > 자막 > 다운로드(.srt)로 받은 파일을 `raw/`에 넣게 한다.
- `내 채널 영상이 아닙니다`: 학교·기관 채널(K-MOOC 등)에 올린 교수님 강의일 수 있다. 본인 강의가 맞고 사용 권한이 있는지 묻고, 맞으면 자막 파일(.srt)을 받아 `raw/`에 넣게 한다.
- `본문이 매우 짧습니다`: 자막이 없거나, 화면에서만 그려지는 사이트이거나, 그림으로만 된 문서다. 다른 형식이나 사이트 저장소(`--repo`)를 제안한다.
- 사용자가 텍스트 파일(`.txt`, `.md`)을 직접 넣은 경우는 이 단계를 건너뛴다.

## 1. 대상 찾기와 종류 판별
- 대상: `raw/` 최상위의 `.txt`·`.md` 중 `processed/*.json`의 `source_file`에 없는 것. 제외: `raw/hold/`, `raw/questions/`(학생 질문은 `/ingest-questions`), `*.meta.json`, `.gitkeep`, 변환 전 원본 문서(.pptx 등, 변환된 `.txt`를 대상으로 한다).
- 종류(`.meta.json`의 `format_hint`가 있으면 우선 참고):
  - **강의 녹취**: 말하는 문체, 수업 인사·마무리, 학생에게 묻는 말 → id `lecture-NN`
  - **강의자료**: 슬라이드·강의노트·실러버스·과제 안내 → id `material-NN`
  - **논문·연구**: 초록·서론·방법·결과 구성, 학술 문체, 연구 보고서·학회 발표문 → id `paper-NN`
  - **칼럼·기고**: 신문·잡지 칼럼, 기고문, 책 원고 → id `column-NN`
  - **블로그 글**: 내 사이트·블로그·뉴스레터 글 → id `post-NN`
- 애매하면 추측하지 말고 묻는다.
- **규칙 3 확인**: 문서 파일은 주소로 확인할 수 없다. 기본 모드에서는 처음 올리는 파일마다 "교수님이 직접 만든 자료가 맞는지"를 짧게 확인한다 (여러 개면 한 번에). 다음이면 멈추고 묻는다: 다른 저자 이름이 제목·첫 쪽에 있음(공저), 출판사 판권·저작권 표시가 있는 출판본, 타 기관 교재·슬라이드를 그대로 옮긴 흔적, 유료 강의 자료.

## 2. 정제
- `raw/`는 절대 수정하지 않는다. 정제본은 `processed/<id>.json`에만 만든다. id 번호는 같은 종류의 기존 최대 번호 + 1.
- 빈 줄·자리표시 문구·쪽 번호·머리말 반복 제거. 자막 파일은 번호·시간 표시를 지우고 말한 내용만 남긴다.
- **학생 정보 제거 (규칙 2)**: 강의 녹취·강의자료 속 학생 이름("김○○ 학생", "민지 씨"), 학번, 조 편성 명단, 성적·출결 언급은 지우거나 "한 학생이", "어떤 조는"으로 바꾼다. 수업 중 학생 발언은 요지만 남긴다. 무엇을 몇 건 바꿨는지 `body_note`에 종류와 건수만 적는다 (이름 자체는 적지 않는다).
- **남의 저작물**: 슬라이드 속 다른 저자의 그림·표·긴 인용은 `[인용: 출처 표기]`만 남기고 내용은 옮기지 않는다. 출처 표기(저자, 연도)는 원문에 적힌 그대로 둔다 — 지어내거나 보충하지 않는다.
- 자동 자막·녹취: `.claude/skills/fix-transcript/glossary.md`를 읽고 **확실한** 전공 용어 오인식만 고친다. 확정할 수 없는 곳은 그대로 두고 목록으로 보고한다.

## 3. 태깅 (표로 먼저 보여 주고 확인받기)
필수 태그 6개: `category`, `format`, `target_audience`, `knowledge_type`, `created_at`, `key_message`.
- `category`·`target_audience`: `taxonomy.md`의 목록 → 기존 `processed/`의 값 → profile.md의 `전공 분야`·`세부 연구 주제`·`주요 학습자` 순서로 고른다. 애매하면 **제안**이라고 표시하고 묻는다.
- `knowledge_type`: 자료가 **주로** 담은 것 하나 — `개념·이론`(무엇인가) / `방법·절차`(어떻게 하나) / `사례·경험`(실제로 있었던 일) / `연구 결과`(연구로 밝힌 것) / `관점·주장`(교수님의 입장·해석). 둘 이상이면 비중이 큰 것, 비슷하면 묻는다.
- `created_at`: 강의일·작성일·발표일. `.meta.json`의 `published_at`(공개일)이 있으면 쓰되, 강의일과 다를 수 있으면 묻는다. `file_modified_at`(파일 수정일)은 **참고만** 하고 그대로 쓰지 않는다. 모르면 묻는다.
- `key_message`: 이 자료가 말하는 것을 **교수님의 표현을 살려** 한두 문장으로. 논문이면 연구 질문과 주된 발견을 원문 범위 안에서.
- 선택: `course`(과목·주차), `reception_grade`(기준이 있는 수치가 있을 때만, `CLAUDE.md`), `coauthors_note`, `views`·`rating` 같은 수치는 메타에 있는 값만.
- **표를 보여 주고 확인받기 전에는 `processed/`에 저장하지 않는다.** 여러 편이면 표 하나에 모아 한 번에 확인받는다.

## 4. 저장과 업로드
1. `processed/<id>.json` 저장. 구조: `id`, `title`, `source_file`(raw/의 .txt 이름), (있으면) `original_file`·`source_url`·`youtube_url`·`youtube_id`·`repo_path`·`course`, `tags{6개 + 선택}`, `views`, `upload_ready`, `missing_tags`, `body_note`, `body`.
2. 미리 검사: `node scripts/upload.mjs --id <id>` (필수 태그, 중복, 개인정보 패턴). 실패하면 이유를 알리고 멈춘다.
3. **검수 에이전트 (필수)**: `--commit` 전에 `data-checker` 에이전트(`subagent_type: "data-checker"`)를 부른다. 프롬프트에 id 목록과 허용한 누락 태그를 적는다.
   - `판정: 업로드 중단` → 올리지 않는다. 문제와 고칠 방법을 한글로 전한다. 중복·학생 정보 문제는 사용자가 "그냥 올려"라고 해도 고친 뒤 다시 검수한다.
   - `확인 필요` 항목, `덮어쓰기 예정` 문서는 사용자에게 알리고 답을 받는다.
4. 확인이 나면 업로드: `node --env-file=.env scripts/upload.mjs --id <id> --commit` (Firestore와도 다시 비교하고, 문제가 있으면 아무것도 쓰지 않는다. `.env`·`keys/` 내용은 읽지 않는다).
   - **`.env`가 없으면 로컬 모드**: 업로드하지 않고 `processed/<id>.json`을 그대로 둔다. 지식 창고는 이 컴퓨터에만 있는 상태이고, 초고(`/draft`, `/make`)는 이것만으로 만들 수 있다. "Firebase를 설정하면 `node --env-file=.env scripts/upload.mjs --all --commit`으로 한 번에 올릴 수 있다"고 알린다.

## 5. 기록
`reports/ingest-log.md` 맨 아래에 날짜, id, 원본(파일·주소), 종류, 태그 요약, 학생 정보 제거 건수(종류만), 용어 교정 수/미수정 목록, 검수 결과, 업로드 결과, 비어 있는 태그를 추가한다. 끝나면 "관리자 페이지 지식 창고 탭에서 확인할 수 있다"고 알리고, 3편 이상 쌓였고 `knowledge-map.md`가 빈 템플릿이면 `/knowledge-map`을, 이미 있으면 "지식 지도에 반영할까요?"를 권한다.

## 자동 모드 (`/ingest auto`)
**원칙: 묻지 않는다. 확신할 수 없으면 올리지 않고 보류한다.** 잘못 올리는 것보다 보류가 낫다.

1. 인자에 파일·링크가 있으면 0단계로 가져온다 (`--list` 생략). 가져오기 실패는 로그에 남기고 계속한다. PDF를 바로 읽지 못하면 0단계의 방법으로 Claude가 직접 읽어 만든다.
2. 대상 파일마다 **독립적으로** 1~4단계를 하되 표 확인은 생략한다. 하나가 실패해도 다음 파일로 간다.
3. 다음 중 하나라도 해당하면 **보류**한다.
   - 종류가 명확하지 않다.
   - `category`·`target_audience`·`knowledge_type`이 `taxonomy.md`나 기존 `processed/` 값 중 명확히 맞는 것이 없다 (자동 모드는 새 값을 만들지 않는다. 단 `processed/`가 비어 있으면 profile.md의 전공·학습자를 그대로 쓴다).
   - `created_at`을 확실히 채울 수 없다 (파일 수정일만 있는 경우 포함).
   - `key_message`를 한 문장으로 정하기 어렵다.
   - 규칙 3 의심: 1단계의 멈춤 조건(다른 저자 이름, 출판사 판권 표시, 타 기관 자료, 유료 자료) 중 하나라도 보인다. (교수님이 `raw/`에 직접 넣은 파일은 교수님 자료로 보되, 이런 표시가 있으면 보류한다)
   - 학생 정보를 확실히 지울 수 없다 (발언이 길게 섞인 녹취 등).
   - 미리 검사 실패, `data-checker`의 `업로드 중단`, `확인 필요` 항목, `덮어쓰기 예정` 문서.
   - `--allow-missing`은 쓰지 않는다.
4. 통과하면 `--commit`으로 올린다. `.env`가 없으면(로컬 모드) 올리지 않고 `processed/<id>.json`을 남긴 채 결과를 **로컬 저장**으로 기록한다 (실패가 아니다). 명령이 오류(네트워크·권한)로 끝나면 **실패**로 기록하고, 이번에 만든 `processed/<id>.json`은 지워 다음에 다시 시도되게 한다 (업로드 여부가 불확실하면 지우지 말고 "업로드 여부 불확실"이라고 적는다).
5. **보류 처리**: 텍스트 원본과 `.meta.json`을 `raw/hold/`로 옮기고(`mkdir -p raw/hold`, 내용 수정 없음, 같은 이름이 있으면 `-2`), 옆에 `<파일명>.hold.txt`로 **보류 사유와 교수님이 결정할 것**을 한글로 적는다. 저장했던 `processed/<id>.json`은 `processed/_hold/`로 옮긴다. 보류 파일은 다음 자동 실행에서 다시 처리되지 않는다 (교수님이 결정한 뒤 `raw/`로 되돌리거나 `/ingest`로 처리).
6. **기록**: `reports/ingest-log.md`에 `## YYYY-MM-DD /ingest auto` → `### 실행 HH:MM` 아래 표로 남긴다 (날짜·시각은 `date`로 얻는다).
   ```
   | 파일 | 결과 | id | 사유·요약 |
   |---|---|---|---|
   | yt-abc123.txt | 업로드 성공 | lecture-06 | 교육심리 / 개념·이론 / 강의 2026-09-20 |
   | file-3주차.txt | 보류 | - | 첫 쪽에 다른 저자 이름: 공저 자료인지 확인 필요 → raw/hold/ |
   ```
   결과는 **업로드 성공 / 로컬 저장 / 보류 / 실패** 중 하나. 개인정보는 값이 아니라 종류와 위치만 쓴다. 마지막 줄: `합계: 성공 N · 로컬 N · 보류 N · 실패 N`.
7. **보고**: 건수, 파일별 한 줄, 보류 사유와 교수님이 할 일. 질문으로 끝내지 않는다.

## 금지
- `.env`, `keys/`의 내용을 읽거나 출력하지 않는다.
- 필수 태그가 빈 채로 조용히 올리지 않는다. 기본 모드에서 사용자 확인 없이 `--commit` 하지 않는다.
- 학생 이름·학번·성적을 `processed/`, 기록, 채팅 어디에도 남기지 않는다.
- 자동 모드에서 삭제, 기존 문서 덮어쓰기, `--allow-missing`, 새 분류값 생성, 검수 건너뛰기를 하지 않는다.
